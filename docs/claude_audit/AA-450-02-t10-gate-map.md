# AA-450-02 — T10 gate map: N7's F1-F9 mapped onto T9's short single-channel content

Per the build task's own instruction: brief map, presented before writing gate code, proceeding
without a stop (no gate below is genuinely uncertain — each decision is directly grounded in
either N7's own code/docstrings or `SKILL_v2.md`/T8's real schema, cited per row).

| N7 gate | Applies to T9? | T9 treatment |
|---|---|---|
| F1 grounding | **Adjusted** | Single atom (not a multi-atom pool), no `[R:atom_id]` tags in tenant-facing copy (old `acp_s4_social/writer.py` never used them either — a visible `[R:...]` tag in a LinkedIn post would look broken). Adjusted gate runs the SAME shared utility (`services.acp_shared.grounding.find_novel_numeric_claims`, ADR-2026-033) sentence-by-sentence against the one chosen atom's text directly — no tag parsing needed since there's exactly one source. |
| F5 atom density | **Removed** | Depends entirely on `[R:...]` tags (not used, see F1) and a 300-word window — gates.py's own docstring already confirms short-form channel bodies (facebook 80-150w, tiktok 100-150w) fall under the window floor and are exempted outright even in N7. T9's content is short-form by design; the gate has no target to apply to. |
| F2 banned patterns | **Adjusted** | Kept, deterministic, cheap. Union of N7's `BANNED_PATTERNS_SEED` lexicon AND `SKILL_v2.md`'s own "Avoid" list (§Avoid) — the two only partially overlap (SKILL_v2.md has "game-changing"/"unlock your potential"/"In today's fast-paced world" that N7's list lacks) — T9 is answerable to its own source doc's list, not only N7's. Kept the B12 verbatim-cited exemption (a flagged phrase that's genuinely quoted from the one atom's own text is not a violation). |
| F3 structural variance | **Removed** | N7's own gate is already `channel != "blog"` → auto-pass; T9 never produces N7-style long-form multi-H2 blog output (that's out of this task's scope entirely — a genuinely different job, confirmed STEP0). Not a new exemption, the same one N7's code already encodes. |
| F4 brief compliance | **Removed, replaced by a light sanity check** | N7's version needs a `Brief.required_h2s`/`word_range` T9 has no equivalent of. Per the build task's own explicit instruction ("không ép số từ chính xác... chỉ chặn trường hợp cực đoan"): kept ONLY an extreme-length sanity check (empty, or wildly longer than any real channel example seen in this codebase) — not a word-count band. |
| F6 route-to-sellable | **Split — one half kept DET, one half folded into F9-equivalent** | `cta_target` missing → N7 holds immediately, non-repairable (`is_repairable` filter). Direct precedent for T9's CTA gap (STEP0's Open Question #2): a request with `cta IS NULL` (unmigrated old data) fails this check immediately, same non-repairable treatment — attempting a "repair" can't invent a CTA no one supplied. `url_alive`/live-tour-page check: **not applicable** — T11 publish doesn't exist for the tenant track, there is no live URL to confirm. "CTA reflected in the body" (N7's blog-only literal-substring check): folded into the F9-equivalent judge's `cta_clear` field instead of a DET substring match, because T9's CTA is a free-text tenant value (e.g. "Book a consultation"), not N7's one fixed brand phrase — semantic judgment fits better than a literal match. |
| F7 FAQ dedup | **Removed** | Only fires on a `## FAQ` section (E4 output); T9 never produces one — same "no target" reasoning as F5/F3. |
| F8 framework judge | **Adjusted, ported** | Same mechanism (Nova Pro judge, binary 1/0 per criterion + mandatory evidence quote, isolated from the writer's own prompt — `services.acp_produce.judge_client.invoke_judge`/`parse_judge_json` reused directly, not rewritten). N7's `FRAMEWORK_RUBRICS` only covers `{hub, PAS, AIDA, hook_story_cta, hook_beats_payoff, reader_as_hero}` — T8's 8 goals (`goals.py`) use `marketing_term` values including SLAP/FAB/BAB/5W1H that have no existing rubric. New rubric items for the missing frameworks are derived directly and mechanically from each goal's own already-written `logic` field in `goals.py` (e.g. Product/Service Explanation's `logic` is literally `"Feature-Advantage-Benefit"` — one criterion per beat) — not invented from scratch. |
| F9 brand/SEO audit | **Adjusted, ported** | Same judge mechanism + failure-code-vocabulary + `GENERIC_AI_WORDING_ANCHOR` pattern, `services.acp_produce.brand.fetch_brand_rubric_text()` reused directly (already real, tenant-scoped, no T9-specific rewrite needed). Rubric fields: N7's own real `facebook` rubric (`_SOCIAL_RUBRIC_FIELDS["facebook"] = [brand_fit, cta_clear, human_read]`) reused verbatim as T9's baseline across ALL channels — not a new invention, and deliberately not a bespoke per-channel field set, matching N7's own documented discipline (ADR-2026-009, "extend from real failures, don't guess the full rubric ahead of data") given T9 has zero real production pieces yet for any channel. `cta_clear` absorbs F6's dropped literal-CTA check (see F6 row) and is checked against the REQUEST's own free-text `cta` value, not a hardcoded phrase (N7's `_CTA_PHRASE_RE`/`Design This Journey` false-positive carve-out doesn't port as-is for this reason — flagged, not silently copied). |
