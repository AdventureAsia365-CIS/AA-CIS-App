## Quy tắc chung cho cả 3 issue (bắt buộc, không lặp lại ở từng mục)

- Mỗi issue: STEP0 (đọc code+schema thật, xác nhận giả định trong description Linear đúng với live code — description có thể lỗi thời) → build → live-verify thật (không chỉ unit test mock) → báo cáo bằng tiếng Việt → chuyển issue kế. KHÔNG dừng lại hỏi giữa chừng trừ khi gặp mâu thuẫn dữ liệu không tự quyết được (ví dụ: code thật khác hẳn mô tả Linear theo hướng ảnh hưởng kiến trúc). Gặp trường hợp đó: dừng, báo cáo rõ, chờ Claude Chat/Nghiệp quyết — không tự suy đoán rồi build tiếp.
- Mỗi issue dùng `git worktree` riêng (không dùng chung 1 thư mục không phải worktree giữa các issue chạy nối tiếp).
- Dọn sạch stash/worktree sau khi xong từng issue, KHÔNG bao giờ `git reset --hard` khi có khả năng còn uncommitted changes — dùng `git stash`.
- Migration-carrying PR: KHÔNG auto-merge, chờ merge tay (Nghiệp).
- PR không mang migration: CI xanh là đủ để auto-merge (quy ước 23/08).
- KHÔNG tự set Linear issue Done. Sau live-verify, comment đầy đủ evidence lên đúng issue, để trạng thái ở "In Progress"/"In Review" — Claude Chat sẽ soát và set Done.
- Sau khi PR merge, kiểm tra Linear có tự động flip issue sang Done không (`get_issue` với `includeRelations: true` để thấy timestamp) — nếu có, tự revert về "In Progress" ngay (đây là automation bug đã biết, không phải lỗi của Claude Code).
- File docs-only (implementation notes, STEP0 audit, live-verify record): KHÔNG mở PR riêng — gộp vào PR build gần nhất của cùng issue, hoặc để uncommitted chờ gộp.
- Nếu có phần FE trong issue: build prompt con (STEP0 output) cho phần FE PHẢI tự viết ra: wireframe/layout mô tả, luồng thao tác từng bước, đầy đủ trạng thái UI (loading/error/empty/success) — trước khi code FE, không được rút gọn thành 1 dòng rồi tự quyết chi tiết.

5. Đọc `subject` schema (AA-511) — xác nhận cột `channel` có sẵn để copy sang `angle_gate_request.subject_id` FK.

### Migration
```sql
ALTER TABLE acp_shared.angle_gate_request
  ADD COLUMN subject_id uuid REFERENCES acp_shared.subject(subject_id);
```
Cột `atom_id`/`channel`/`goal` cũ giữ nguyên. `channel` giờ luôn copy từ `subject.channel` lúc tạo request, không tự do chọn.

### Build

2. `services/acp_angle_gate/service.py::create_request()` nhận `subject_id`, lấy `channel` từ subject (không nhận `channel` tự do nữa).
3. Đổi ranking 3 angle sang công thức đo được (theo ADR 0004 đọc ở STEP0.2): Segment/Route Score (AA-511) + số câu PAA angle trả lời được + số vi phạm avoid-list của Channel (đếm được, không LLM-opinion).
4. Sửa `tenant_pool.py`/`v1_publish.py` nếu STEP0.3 phát hiện còn giả định sai.
5. Frontend `t8-angle-gate/page.tsx`:
   - Header cố định hiện Subject + Channel đã chọn (không sửa được ở đây).
   - 2 bước: chọn Goal (8 thẻ, giữ nguyên) → 3 thẻ Angle, mỗi thẻ có badge số đo được (vd "trả lời 2/4 câu PAA", "0 vi phạm avoid-list") thay vì chỉ text mô tả suông.
   - Viết wireframe/luồng/trạng thái UI đầy đủ trước khi code (theo quy ước chung ở trên).
