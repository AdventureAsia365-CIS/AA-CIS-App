# AA-560 — "07 · Platform Stats" replaces Cross-Tenant Oversight + Force unpublish moves to Content Trace (06)

## STEP0 / Gap found before build

AA-558's "2/4 sections trùng 100%" claim only holds for Publish Log's READ side. The mutating
"Force unpublish" action (`POST /admin/a4/publish-log/{id}/unpublish`, AA-455) has no UI home
anywhere except the page this issue asks to delete — Content Trace (06) shows `publish_status`
read-only, no unpublish button. Flagged to Nghiệp before writing any code; confirmed decision
(09/09/2026, folded into the Linear issue itself): move Force unpublish into Content Trace (06)
as an added scope item, keep page "07" to Review Log + Trust Ramp + new aggregate only. Old page
is deleted only after BOTH are live-verified.

## Decisions

- New route: `/admin/platform-stats`, sidebar label "07 · Platform Stats" (page title also shown
  as "07 · Platform Stats" per Content Trace's own `06 · Content Trace` H1 convention).
- `SocialContentSubNav.tsx` (AA-575): added a 6th nav key `"platform_stats"` to `SubNavKey`, one
  more real `<Link>` row after "06 · Content Trace" — same shape, no per-page special-casing.
- Review Log + Trust Ramp: markup/fetch logic copied verbatim from `a4-oversight/page.tsx` (same
  endpoints, same field shapes) — only the sort mechanism is new (was entirely unsortable before).
  Reused Content Trace's exact `Sort`/`sortValue`/`toggleSort` pattern (AA-572/575) rather than
  inventing a second one.
- New aggregate endpoint: `GET /admin/a4/platform-stats` (api/routers/admin_a4.py) — 3 real SQL
  GROUP BYs (by_channel, by_status, top_gate_failures via `jsonb_array_elements(gate_ledger)`),
  no LIMIT on the source rows (fixes the old client-side rollup's `limit=200` window problem
  AA-558 Phần 1 Q3 flagged). Verified against the old rollup's own numbers before wiring the UI
  to it (see "Verify" section below).
- Force unpublish button added to Content Trace's accordion (only on `publish_status ===
  "published"` rows) — same `handleForceUnpublish` confirm-dialog shape as the old
  `a4-oversight` page, calling the same untouched backend endpoint.
- `admin_a4.py`'s `review-log`/`trust-ramp`/`publish-log`/`content-log`/force-unpublish endpoints
  are otherwise byte-for-byte unchanged — only a new `platform-stats` handler is added to the file.

## Changed vs. original requirement

- Added Force-unpublish to Content Trace (06) — not in AA-560's original text, added after the
  gap above was found and confirmed with Nghiệp; tracked in the Linear issue's own edit history.

## Tradeoffs

- Trust Ramp's per-tenant grouped mini-tables get the same click-to-sort headers as Review Log
  (sorting packets within each tenant group) rather than skipping sort there — issue explicitly
  says "any table/list", and Trust Ramp's grouped tables are still tables.
- Aggregate section (platform-stats) is NOT built as an interactively-sortable table — it is a
  ranked, already-sorted-by-count list/stat-tile group, which has only one natural ordering
  dimension. Full per-column sort applies to Review Log + Trust Ramp (genuine multi-column
  tables), not to this section.

## Should know

- `acp_shared.content_piece.gate_ledger` is a real Postgres JSONB column — `jsonb_array_elements`
  works fine in SQL regardless of the app's own asyncpg jsonb-codec gap (that gap only affects how
  Python decodes a fetched value, not how Postgres evaluates jsonb functions server-side).
- `/admin/a4/publish-log` (GET) is still read by `frontend/app/admin/tenants/page.tsx` — left
  fully untouched.
