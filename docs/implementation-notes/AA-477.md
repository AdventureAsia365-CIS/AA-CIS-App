## Context

## Decisions
- Kept `services/acp_s4_blog/cms/wordpress.py` + `cms/base.py` exactly as STEP0 required — T11
  (`v1_publish.py`/`v1_integrations.py`) imports them directly. Verified the import chain
  BEFORE deleting anything else in the directory (`grep` for every file's callers individually,
  not just the 2 files STEP0 already flagged) — found 4 more files (`models.py`,
  `sample_loader.py` in `acp_s4_blog/`, `embeddings.py`, `image_sourcer.py` in `acp_s4/`) that
  STEP0 hadn't explicitly enumerated; traced each to confirm they only feed the
  already-confirmed-dead `validator.py`/`graph.py` lineage, not T11.
- 2 test files needed surgical edits instead of whole-file deletion because they mixed dead-code
  tests with live/unrelated tests: `tests/test_eventbridge_contract.py` (kept
  `services.acp.handler` + `services.acp_shared.idempotency` + S4-trigger-Lambda tests — none of
  those modules were in this task's deletion scope, removed only the one test importing the now-
  deleted `api.routers.v1_s3`) and `tests/unit/test_pgvector_calibration.py` (kept the 4 pure
  TF-IDF tests using `scripts/calibrate_pgvector_threshold.py` — untouched, out of scope —
  removed only the 3 tests importing the now-deleted `services.acp_s4.embeddings`).
- Explicitly did NOT touch `services/acp/handler.py`, `services/acp_shared/idempotency.py`,
  `api/lambda/s4_trigger/handler.py` even though they reference the dead `acp_shared.acp_runs`/
  `acp_stage_runs` tables too (per STEP0's own caller inventory) — none of these were named in
  this task's scope. Flagging for a possible future round rather than silently expanding scope.
- Did not touch the 5 orphaned frontend pages (`admin/pipeline/{s1,s2,s3,s4-blog,s4-social}`) —
  explicitly out of scope per the task (backend/infra/DB only). They will now hit real 404s if
  visited by direct URL (previously they got empty JSON from a live-but-pointless endpoint) —
  same "still reachable by URL, not linked" status as before, just louder if someone tries.

## Tradeoffs
- Chose file-level surgery over "delete the whole package/test file for simplicity" wherever a
  package or test file mixed dead and live code — more edits, but the alternative (package-level
  deletion) is exactly the mistake STEP0 flagged as the real risk.

## Scope expansion (found during build, not in the original file list)
While drafting the Terraform destroy for the 2 Lambdas (Phase 2), found their REAL source
directories were never named in STEP0's or the task's explicit file list: `services/acp_s3/`
(the actual `aa-cis-dev-acp-s3-campaign-planner` Lambda source — separate from the deleted
`v1_s3.py` router, confirmed via `scripts/package_lambdas.sh`) and `services/acp_s4_evaluate/`
(the actual `aa-cis-dev-acp-s4-evaluate` Lambda source). Leaving these in place while destroying
the Lambdas via Terraform would have broken the very next `deploy-dev.yml` run — its
`deploy-lambdas` job loops over a hardcoded function-name list including `acp-s4-evaluate` and
`acp-s3-campaign-planner` and would hit `ResourceNotFoundException` trying to
`update-function-code` on a Lambda Terraform had already destroyed.
- Verified 0 external callers for both directories first (same file-by-file grep rigor as
  Phase 1) before deleting.
- Removed both from `git rm`, removed their `package_*` functions from
  `scripts/package_lambdas.sh`, removed their names from `deploy-dev.yml`'s `deploy-lambdas` loop.
- Confirmed `api/schemas/run_context.py` (which `package_acp_s3_campaign_planner()` used to vendor
  into the Lambda zip) is NOT touched — it's still imported by `api/services/run_context_db.py`,
  which `services/export/handler.py` (live A0-A3 admin pipeline) uses. Only the vendoring COPY
  step (inside the now-deleted packaging function) went away, not the source file itself.
- Left `services/acp_s3/tests/` deletion as a side effect (nested inside the deleted directory) —
  confirmed via `pytest --collect-only` before/after (1718 tests both times) that these were never
  part of the `tests/` pytest run scope to begin with (no `pytest.ini`/`testpaths` pulls them in),
  so this had zero effect on the suite either way.
