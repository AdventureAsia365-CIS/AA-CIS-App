# AA-344 — Upload History: surface rows_landed/rows_dropped

## Decisions
- Followed the issue's own proposal verbatim (already fully specced in AA-343 Part C's
  writeup) — no new design decisions needed.
- LEFT JOIN, not INNER JOIN, on `shared.pipeline_runs.batch_id` — a source ingested before
  migration 091 (no `ingest_details` yet) or any edge case where `batch_id` has no matching
  `pipeline_runs` row must still appear in Upload History with `rows_landed`/`rows_dropped`
  simply `null`, per the issue's own "degrades gracefully" requirement — never drop the row.
- `int(...) if ... is not None else None` cast on both fields: `->>'...'` on a jsonb column
  returns text, and the frontend needs a real number (or null) to do `> 0` comparisons and
  arithmetic display — not a string.

## Changed
- `api/routers/admin_pipeline.py::get_upload_history()` — LEFT JOIN `shared.pipeline_runs pr
  ON pr.batch_id = rs.batch_id`, adds `rows_landed`/`rows_dropped` (both `int | None`) to the
  response shape.
- `frontend/app/admin/upload/page.tsx`:
  - `UploadHistoryItem` interface: `rows_landed`/`rows_dropped` fields.
  - Table header: "Tours Parsed" → "Parsed / Landed" + new "Dropped" column.
  - Cell: `"{row_count} / {rows_landed}"` when `rows_landed` is known, else just `row_count`
    (pre-091 sources unchanged visually). New "Dropped" cell: red `Badge` "{n} dropped" when
    `rows_dropped > 0`, muted "0" when `rows_dropped === 0`, "—" when `null` (no data yet).
- `tests/unit/test_aa344_upload_history_landed_dropped.py` — 3 new tests (real
  landed/dropped surfaced, pre-091 source degrades to null, 0-dropped is a real int 0 not
  confused with null).

## Tradeoffs
- No backfill of `ingest_details` for historical sources ingested before migration 091 —
  matches the issue's own explicit "NULL for any source ingested before migration 091 (no
  backfill needed)" instruction.
- No new migration — `ingest_details` (migration 091) and its write path (`services/
  ingestion/handler.py`) already shipped in AA-343 Part C; this issue is read-side only, as
  its own "Should know" section states.
