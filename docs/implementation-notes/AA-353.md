# AA-353 — structured per-day itinerary output + target ratio + auto-nudge + CI regression guard

## Decisions
- **Downstream needs zero changes.** `generate_node` will parse the model's structured
  `itineraries` array, clamp/nudge it, then SERIALIZE it back to the exact canonical string
  format (`"Day N — Title\nBody\n\nDay N+1 — ..."`) before returning state — so `validate_node`,
  `judge_node`, `brand_audit_node`, `flag_fix_node`, `_normalize_generated` (v1_pipeline.py),
  `generated_content.aa_itineraries` (TEXT column), and every HITL/export reader keep receiving a
  plain string exactly as before. Confirmed by reading all of them (see "Should know").
- **No new migration/table.** `silver_aa_internal.generated_content.metadata` (migration 048,
  JSONB, already the home of `score_overall`/`fallback_used`/`batch_id`/`revalidate_*`/`judge` per
  AA-213/AA-209's own precedent in `_build_generated_metadata()`, admin_pipeline.py:150-189) is
  where the new `itinerary_compression` flag/metric data goes — same pattern as `judge`, added
  conditionally. `shared.pipeline_runs.ingest_details` (migration 091) was considered and rejected:
  091's own comment explains it's deliberately scoped to ingest-level diagnostics, not
  quality/compression signals, to avoid exactly the semantic collision this would cause.
- **Day-title formatting no longer trusted to the model.** The new array contract asks the model
  for `{"day": int, "title": "...", "body": "..."}` — `generate_node` builds the literal
  `"Day N — Title"` header itself during serialization. This is a deliberate side-effect: it
  eliminates the em-dash/`--`/`||` inconsistency `validate_node`'s string-cleanup regex
  (graph.py:349-358) exists to patch, for the array path. The regex stays (harmless, and still
  needed as a fallback for the rare case `generated["itineraries"]` comes back as a plain string).
- **Per-day source word counts computed in code, not by the model** — unlike AA-352, which
  explicitly chose to let the LLM self-extract `itinerary_day` because a regex pre-pass over
  free-text day labels was found unreliable (AA-352 STEP 0). That choice doesn't transfer here:
  AA-353 needs the per-day source word count as a **prompt INPUT** (to state the target ratio),
  not an extraction target, so it must exist before the LLM call. Confirmed via AA-352's own notes
  that no reusable day-boundary parser exists in the codebase — writing a fresh one, line-anchored
  (`^\s*Day\s*#?\s*(\d{1,3})\b`, `re.MULTILINE`, first match per line only) specifically to avoid
  the false-positive AA-346 flagged ("Easy Day 82 km Tarmac Road" matching on the "82"): anchoring
  to line-start means a mid-line "Day 82" inside a title never matches. Falls back to
  `total_words / estimated_day_count` (from `tour.duration`) with a logged warning when fewer than
  2 day-markers are found — not silent.

## Should know (downstream read, STEP 0 continuation)
- `validate_node` (graph.py:340-384) and `v1_pipeline.py::_normalize_generated` (lines 29-70) BOTH
  already contain dead/speculative code that normalizes `generated["itineraries"]` when it's a
  `list[dict]` — but using field name `description` (not `body`) and joining with `"\n\n---\n\n"`
  plus a markdown `*Activities: ...*` line for an `activities` field. This literally violates rule
  5's own "Do NOT use... markdown" / "Do NOT use "--"" constraints. It's never triggered in
  production today (the current prompt never asks for an array) — likely defensive coding for
  provider variance (GPT-4.1 tier). **Not touched by this change** — AA-353's new code in
  `generate_node` serializes to canonical string BEFORE returning state, so this dead code stays
  dead (never exercised by the new path either). Flagging as a pre-existing latent inconsistency,
  out of scope to fix here per the issue's explicit "don't expand scope" constraint.
- `judge_node` (`_build_judge_prompt`) and `brand_audit_node` both do `str(generated.get(
  "itineraries"))[:N]` — safe either way, but will always see the post-serialization string.
- `admin_pipeline.py`'s real DB-write path (`/admin/pipeline/run-tour`-equivalent handler, lines
  ~460-534) confirms `generated_content.aa_itineraries` is TEXT and already has a defensive
  `str(_itin)` coercion (line 515-517) — 3rd occurrence of the same defensive pattern, all now
  permanently unreachable for the array path since `generate_node` never returns a list.
- `services/content_generation/graph.py`'s `generate_node`/`build_graph()` is called from exactly
  one place, `api/routers/v1_pipeline.py:96` (`_rewrite_tour`), which is in turn called from
  `admin_pipeline.py`'s real-write handler AND from `services/eval/regression.py::run_s1_old_eval`.
  `s1_from_atom.py` remains fully separate (own `max_tokens=4096` at line 409) — confirmed
  untouched, consistent with STEP 0's original scope confirmation.
- **`services/eval/regression.py`** (not `eval/regression.py` — task's assumed path doesn't exist;
  actual path under `services/`) is an ON-DEMAND-ONLY eval gate (AA-289), not wired into any
  push/PR CI trigger — `.github/workflows/eval-regression.yml` is `workflow_dispatch`-only. It
  already writes to `shared.prompt_eval_runs.details` (JSONB) — extending `run_s1_old_eval()`'s
  `details` dict with `itinerary_compression` metrics needs no schema change either.
- **Golden Tours 20 fixture gap (flagging, not silently proceeding):** AA-339's own issue text
  states the existing `CIS_Golden_Tours_20_v1.xlsx` (baseline avg 9.9/10, "0 fail" — near-perfect)
  is NOT guaranteed to cover long/dense (>9-10 day) tours — the exact scenario AA-353 targets.
  AA-339/AA-346's real compression evidence came from a separate 30-tour Laos set (AA-340) and 5
  specific real `raw_tours` tour_ids (AA-346), not this fixture. Using golden-20 for the CI
  regression guard anyway (steps 1/2/6 explicitly ask for it, and it's what's actually wired into
  CI) — but supplementing the "read by eye" qualitative check (VERIFY step 2, ≥3 real tours) with
  the known-compressed AA-346 tour_ids instead of hoping golden-20 happens to contain one.
- **AA-339 length-group boundary — partially unrecoverable, not inventing the missing part.**
  AA-339's issue text gives "long-dense" = **>9-10 days** explicitly (quoted). It does NOT give a
  numeric medium/thin split — that was a human categorical assignment on a dedicated 30-tour set
  ("10 dài-dày + 10 trung bình + 10 mỏng") that isn't in this repo, and the word-count-based "rich"
  threshold AA-339 itself flagged as suspect (`words>=400 OR (days>=4 AND words_per_day>=35)`) was
  never confirmed. Per the issue's own instruction not to invent a new grouping: implementing
  **2 buckets** only — `long` (duration_days >= 9, AA-339-sourced) and `other` (everything else) —
  rather than fabricating a medium/thin numeric boundary. Flagging this explicitly rather than
  presenting 3 buckets as if AA-339-sourced.

## Changed
- `services/content_generation/prompts.py`:
  - New `parse_source_day_word_counts(itineraries_raw, duration_hint)`: line-anchored `Day N`
    boundary parser (`^\s*day\s*#?\s*(\d{1,3})\b`, `re.MULTILINE`-equivalent via per-line match) —
    returns per-day word counts AND per-day text. Falls back to an even split of total words over
    an estimated day count (from `duration_hint`) when fewer than 2 markers found, logged via
    `structlog` warning `itinerary_day_parse_fallback`, never silent.
  - `build_rewrite_prompt`: injects a new `PER-DAY SOURCE LENGTH` block (day → source word count)
    into the user prompt, computed via the function above.
  - `SYSTEM_PROMPT` rule 5: no longer mandates the model produce the literal `"Day N — Title"`
    string itself (that's now built deterministically in code); adds the 0.7x-1.3x per-day length
    instruction, referencing PER-DAY SOURCE LENGTH.
  - Output JSON contract: `"itineraries"` changed from a bare string to
    `[{"day": int, "title": str, "body": str}, ...]`.
- `services/content_generation/graph.py`:
  - New `ITINERARY_CLAMP_MIN`/`MAX` (0.6/1.5), `_ITINERARY_NUDGE_SYSTEM_PROMPT`,
    `_nudge_itinerary_day()` (one small targeted LLMRequest, `model_tier="haiku"`, exactly one
    attempt — caller never retries), `_process_itineraries()` (clamp-check + nudge + serialize
    array back to the canonical string, mutating `generated["itineraries"]` in place).
  - `generate_node`: calls `_process_itineraries` right after JSON parse succeeds; folds nudge
    call cost/cache-tokens into the totals already being accumulated; returns new
    `itinerary_day_ratios` state key.
  - `ContentState` TypedDict: added `itinerary_day_ratios: list` — REQUIRED, not cosmetic

- `api/routers/v1_pipeline.py`: `_rewrite_tour`'s return dict propagates
  `itinerary_day_ratios": result.get("itinerary_day_ratios", [])` — same "strip class" as the
  existing judge_*/fallback_used/prompt_version propagation lines right above it (that dict is
  rebuilt from scratch, not a passthrough).
- `api/routers/admin_pipeline.py`: `_build_generated_metadata` adds an `itinerary_compression`
  block (`day_ratios`, `nudged_day_count`, `violation_day_count`, `still_violating_after_nudge`)
  to `generated_content.metadata`, omitted entirely when `itinerary_day_ratios` is empty — same
  guard style as the existing `judge` block right above it.
- `services/eval/regression.py`:
  - `ITINERARY_LONG_TOUR_DAY_THRESHOLD = 9` (AA-339-sourced, see "Should know" for why this is

## Tradeoffs
- **Ratio denominator is the model's OWN reported body, word-count only** (not title). A day's
  `title` is a short label, not prose — including it in the ratio would penalize a longer/shorter
  title unrelated to the actual compression bug this issue targets.
- **Positional fallback when day numbers don't line up** (`_process_itineraries`, `position <
  len(source_ordered)` branch): if the model renumbers days (e.g. starts at 1 when the source's
  parsed markers were irregular), ratio-matching falls back to i-th-returned-day vs i-th-source-day
  rather than dropping the check. Simple and good enough given rule 5 explicitly tells the model to
  preserve day numbers — this is a defensive fallback, not the expected path.
- **Nudge call has no JSON schema/strict output enforcement**, same as the main call — relies on
  the existing `json.loads` + `repair_json` salvage pattern already proven in `generate_node`. If
  the nudge reply itself fails to parse, `_nudge_itinerary_day` falls back to keeping the
  ORIGINAL (out-of-clamp) title/body unchanged (`parsed.get("title") or current_title`) rather
  than crashing the whole tour — one bad nudge degrades to "flagged, unfixed", never a pipeline
  failure.
- **`_detect_itinerary_regression` is file-based, separate from the existing DB-row
  `prompt_version`-keyed mechanism** in the same module. Considered unifying them, but the
  existing mechanism compares against "most recent PRIOR row with a DIFFERENT prompt_version" —
  every run of `run_s1_old_eval()` writes a NEW row, so "the baseline" drifts forward run over
  run. AA-353 explicitly wants a FIXED, deliberately-captured comparison point ("PHẢI có trước khi
  đổi code") that only moves on an intentional re-baseline — a committed file matches that
  semantic; reusing the existing rolling-row mechanism would not.
