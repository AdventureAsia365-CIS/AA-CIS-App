# AA-428 — CatalogTab.tsx calls /api/tenant/v1/quota, which doesn't exist

## Decisions
- Removed the dead `/v1/quota` call rather than building a real endpoint. STEP 0 confirmed:
  no `/v1/quota` route anywhere in `api/routers/*`, no DB table/column for a per-tenant
  "rewrites remaining" concept (`acp_shared.acp_quota_ledger` is a different, dead ACPv1
  S2/S3/S4 concept, never read; `raw_tours.rewrite_count` has 0 callers), and no other real
  enforcement mechanism limits rewrite count today — the only live limiter on `/v1/tours/pool/
  {id}/rewrite` is the generic per-minute `rate_limit_middleware` (RPM throttle), unrelated to a
  monthly rewrite-credit concept. Git blame (`3d69941`, AA-57) shows this was speculative
  frontend work written ahead of a backend that was never built, deliberately "graceful silent"
  by original design — not a broken/renamed route.
- Scope widened (with Nghiep's explicit confirmation) to also remove `QuotaBar.tsx` and its
  wiring through `ApiPlayground.tsx`/`ApiTab.tsx` — a second, independent dead consumer of the
  same `rewrites_remaining` field shape, fed from `/admin/billing` (a real, working endpoint)
  but reading fields (`rewrites_remaining`, `rewrites_limit`, `api_calls_month`) that don't exist
  at the top level of that response. `QuotaBar.tsx` had exactly one caller and no other
  responsibility, so the whole file was deleted rather than partially edited.
- Real quota enforcement, if the business wants it, is out of scope — tracked separately as
  AA-489 (Backlog).

## Changed
- `CatalogTab.tsx`: removed `quota` state + its `/api/tenant/v1/quota` fetch effect, and the
  "You have N credits remaining" line in the "Request New Version" confirm dialog. Kept the
  dialog's main message ("This will use 1 rewrite credit."), `showQuotaConfirm` state, and both
  Cancel/Confirm buttons unchanged — none of those depended on the dead fetch.
- `ApiPlayground.tsx`: removed the `quota` prop and `<QuotaBar>` render.
- `ApiTab.tsx`: removed the `billing` state + `/api/admin/billing` fetch (its only consumer was
  the `quota` prop passed to `ApiPlayground`) and the now-unused `useEffect` import. Left the
  `/admin/billing` entry in the static `ENDPOINTS` doc table untouched — that's an unrelated
  reference-doc string, not tied to the removed fetch.
- Deleted `api-playground/QuotaBar.tsx` entirely.

## Tradeoffs
- Could have kept `QuotaBar`/`billing` and just fixed the field-shape mismatch against
  `/admin/billing`'s real response — rejected: that would resurrect a "rewrites left" UI backed
  by numbers that still don't map to any real enforcement (same root problem AA-428 flags), and
  widens this bugfix into a feature build that belongs in AA-489 instead.

## Should know
- No backend/DB changes in this PR — pure frontend dead-code removal, no migration.
- Build (`next build`) and typecheck pass clean. Lint has pre-existing repo-wide findings (117
  errors/63 warnings, e.g. `react-hooks/set-state-in-effect` on unrelated pages) — none of them
  fall inside the diff hunks touched by this change (verified via `git diff --unified=0`).
