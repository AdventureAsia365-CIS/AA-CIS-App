## Additional real, reachable instance found (issue's own "việc cần làm" #3 — cost tracking by
model name)

`bedrock_satellite.py`'s own audit trail already gets this RIGHT: `invoke_claude()` returns
`model_used="sonnet-4-6"` (a real, accurate label, `bedrock_satellite.py:244`), and
`_call_bedrock_satellite()` wraps it as `model_used=f"satellite-{result.model_used}"` =
`"satellite-sonnet-4-6"` (`client.py:268`). That accurate string is what
`services/content_generation/graph.py:442` puts into `result["model_used"]`, which
`api/routers/admin_pipeline.py:544` then writes into `silver_aa_internal.generated_content.
model_editorial` on every real S1 rewrite that falls through to the satellite (the common case —
acc2-native Sonnet is blocked for channel-program accounts, AA-291/AA-329).

But `admin_pipeline.py` has 2 places (lines ~3258-3261 and ~3283-3286, the `/admin/pipeline/stats`-
class cost-by-model dashboard queries) that re-derive a DISPLAY label from that same column via
`CASE WHEN ... LIKE '%sonnet%' THEN 'claude-sonnet-4-5'` — i.e. it takes the accurate
`model_editorial` string (which may literally be `"satellite-sonnet-4-6"`), pattern-matches only on
the substring `"sonnet"`, and re-labels it back to the hardcoded, wrong-for-this-row
`'claude-sonnet-4-5'`. This is a real, reachable, second instance of exactly the class of bug the
issue's own "việc cần làm" #3 asks to check for ("logging, cost tracking theo model name") — not
hypothetical, confirmed by tracing the actual column write path end to end.

## Decisions

1. **Which side is "wrong": rename the satellite to 4-5, or document 4-6 as intentional?**
   Going with **document as intentional, no model/behavior change** — matching the issue's own
   "Ràng buộc" section verbatim ("thuần là lệch tên biến/comment, không phải thay đổi hành vi/kiến
   trúc"). Evidence for treating 4-6 as the deliberate, real satellite model (not a copy-paste
   bug): `bedrock_satellite.py`'s own top-of-file record shows it was invoke-tested independently
   (16/07/2026, both accounts, "STATUS: VERIFIED THẬT") specifically AT 4-6, has since been the
   sole production Sonnet path for months (acc2-native Sonnet blocked for channel-program orgs
   per AA-291/AA-329), and IAM policy on both satellite roles is scoped narrowly to the 4-6
   inference-profile ARN — changing the invoked model to a literal 4-5 profile would need new IAM
   scoping + a fresh availability check on both satellite accounts, a real behavior/infra change
   explicitly out of this issue's scope. Renaming `BEDROCK_SONNET` itself was also rejected: it's
   correctly named for its OWN real use (the acc2-native T1 tier, which really does run 4-5) and
   is reused elsewhere purely as a tier selector / COST_TABLE key, not as a literal-model claim —
   renaming it would ripple through ~10 call sites in `client.py` plus a test import
   (`tests/unit/test_aa324_satellite_prompt_cache.py`) for a naming-only gain.
   → Fix: comments only, at the two points of dual meaning (pricing.py's definition,
   bedrock_satellite.py's inference-profile table), cross-referencing each other and AA-348 by
   name, per the issue's own explicitly-offered option 2 ("thêm comment giải thích rõ tại sao 2
   tier có thể khác version nếu đó là cố ý").
2. **The admin_pipeline.py dashboard mislabel** — fix, not just document. Changing
   `'claude-sonnet-4-5'` → `'claude-sonnet'` (version-neutral) in both CASE expressions is a
   one-line-each, purely cosmetic display-string change (no query shape, no stored data, no other
   endpoint touched) — safe to fix directly rather than defer, unlike decision 1 above which would
   be a real infra/behavior change.
3. **Not touched**: `.claude/CLAUDE.md`'s own "BEDROCK CONFIG" section states
   `us.anthropic.claude-sonnet-4-5-20251001-v1:0` — a DIFFERENT date suffix (`20251001`) than
   pricing.py's real `20250929`. This is a separate, pre-existing doc/reality drift, not what
   AA-348 is about (AA-348 is specifically the client.py-constant vs bedrock_satellite.py-model
   mismatch) — noted here so it isn't lost, not fixed in this PR.

## Tradeoffs

- Did not attempt to make the admin dashboard's cost-by-model breakdown version-accurate (e.g.
  parsing "satellite-sonnet-4-6" vs "us.anthropic.claude-sonnet-4-5..." into distinct rows) —
  that's a real, larger, separate improvement (would need to decide whether native vs satellite
  Sonnet should even be broken out as different dashboard rows) worth its own ticket, not a
  one-line naming fix.
- Did not fix the cost-table pricing-by-version gap noted in `services/acp_produce/
  generation.py:310-313` (satellite Sonnet-4-6 calls are priced at the native constant's rate,
  since Anthropic has not published separate Bedrock pricing for 4-6 as of this note) — that
  comment already exists (AA-505) and documents the same limitation; no evidence surfaced during
  this task that the price actually differs, so inventing a new rate would be speculative.

## Should know

- No DB migration, no behavior change to which model gets invoked on any tier — pure comments +
  one cosmetic display-string fix.
- `admin_pipeline.py`'s dashboard queries have no existing test coverage locking in the old
  `'claude-sonnet-4-5'` label (confirmed via grep before editing) — the change is live-verified by
  reading the query result directly, not by a new/changed unit test.
