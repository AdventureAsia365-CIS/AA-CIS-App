## Decisions
- **Width fixes, not full-bleed** (per the issue's own instruction): `AngleGateWizard.tsx`'s
  maxWidth 720→880 (a deliberate, moderate increase — its Goal/Angle cards are single-column
  prose, not a grid; going edge-to-edge (~1148) would stretch lines well past a comfortable
  reading width). `t11-publish/page.tsx`'s maxWidth 640 was removed entirely and replaced with a
  narrower cap (560) around ONLY the WordPress connect-form section (its `<input>`s are
  `width:100%`, so they need *some* cap) — `PublishPendingList`'s content-preview cards now use
  the full width, matching `ReviewList.tsx`'s identical card pattern.
- **Sticky pattern — one per page, not two**: tried making both a page-level H1 AND a
  Card-nested tab/filter bar sticky on the same page; reverted the page-level one. `<main>`'s
  scroll container (`layout.tsx`) gives every `position:sticky; top:0` descendant the SAME
  offset regardless of nesting depth — two sticky elements on one page collide at the identical
  position. Kept only the Card-nested one (the one that actually matters — which channel/filter
  you're viewing while scrolling a long list); the page H1 scrolls away, same as before, and the
  breadcrumb above already shows the page name at all times.
- **Real bug found + fixed while building this**: a sticky bar's `top:0` resolves to `<main>`'s
  own padding edge (28px down), not its border-box edge — the 28px band between them is *inside*
  the padding box, so `overflow-y:auto` does not clip it. Once a sticky bar is stuck, later
  content scrolling through that specific 28px band renders **above** the sticky bar, uncovered
  (caught by an actual scrolled screenshot — a WordPress form input rendering on top of the
  "Publish" heading). Fixed by making `StickyBar` (new shared component, `ui.tsx`) bleed that
  28px by default (`bleedTop` prop) on every usage, not just page-level ones — the leak exists
  at any nesting depth since the offset is constant.
- New `StickyBar` component added to `ui.tsx` (the portal's shared design-token file) rather than
  repeating the sticky/z-index/background boilerplate at each of the 3 call sites — this is the
  "design token" consistency pass the issue asked to fold in if convenient.

## Tradeoffs
- Considered removing `AngleGateWizard`'s width cap entirely instead of bumping it — decided
  against it: the content is prose (why_it_works/formula_fit/best_final_style), not a grid, so
  full width would hurt readability more than the current whitespace hurts the layout.
- Considered a "stacked sticky" approach (page header sticks at top:0, Card header sticks at
  top:<page header height>) instead of dropping the page-level sticky — rejected as needless
  complexity/fragility (depends on a dynamic height) for a page title that isn't the part users
  actually need pinned while scrolling a list.
