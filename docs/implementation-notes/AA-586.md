# AA-586 — topbar global search no longer auto-navigates on focus

## Decisions

- Removed the `onFocus={goToPool}` handler entirely rather than gating it on `pathname`.
  `handleSearchKey`'s existing Enter-with-text → `goToPool()` path already covers the one
  legitimate "search then jump to Browse Tours" use case, and nothing in the codebase relied on
  focus-triggered navigation (`grep`-confirmed only reference was the removed prop). A
  pathname-gate would have been a more complex fix for a behavior that had no real justification
  in the first place.
- Left `goToPool()` and `handleSearchKey` untouched — only the `onFocus` binding was removed.

## Changed

- `frontend/app/(tenant)/portal/layout.tsx`: removed `onFocus={goToPool}` from the topbar search
  `<input>`. Updated the stale comment above `goToPool()` that described the old
  focus-triggers-navigation behavior.

## Tradeoffs

- Considered pathname-gating (`onFocus` navigates only when NOT already on a portal page) instead
  of outright removal — rejected because it preserves the same surprising-navigation risk on any
  future page that also happens to not be `t1-rewrite`, for zero behavioral gain over the simpler
  Enter-triggered flow.

## Should know

- `t1-rewrite`'s live-filter-while-typing behavior (`PoolTab.tsx`'s `externalSearch` prop) is
  driven by `onChange` syncing `globalSearch` into context, not by `onFocus` — removing `onFocus`
  does not affect it. Confirmed via Playwright: typing "Korea" + Enter on `t1-rewrite` still
  filters the list correctly.
- Live-verified via a local `next dev` server (Turbopack) pointed at the real ECS/RDS backend,
  real WanderLux Travel tenant login (generate-key + `/tenant-login`), all 3 scenarios (t4-pool
  focus, dashboard focus, t1-rewrite focus+filter) confirmed correct; the "before" reproduction
  was also captured live against production (`aa-cis.lumiguides.it.com`, still on the pre-fix
  `main` at the time), confirming the bug and the fix's before/after delta.
