### 2. F3_structural_variance — exact logic (code: `gates.py` lines 159-196)

Blog-only (`channel != "blog"` → auto-pass — facebook/tiktok never run this gate at all). Three
**independent** checks, ANY failing fails the gate:

```python
paras = [p for p in body.split("\n\n") if p.strip() and not p.startswith("#")]
# (1) at least one genuinely-one-sentence paragraph must exist:
any(len(re.split(r"(?<=[.!?])\s+", p.strip())) == 1 and len(p.split()) >= 2 for p in paras)

# (2) with >=3 "## " H2 sections, longest must be >=1.4x the second-longest (by word count):
sections = re.split(r"^## ", body, flags=re.MULTILINE)[1:]
if len(sections) >= 3:
    lens = sorted(len(s.split()) for s in sections)
    fail if lens[-1] < lens[-2] * 1.4

# (3) at most 1 "\n\n"-delimited block starting with "- "/"* " in the whole body
blocks = len([b for b in body.split("\n\n") if re.match(r"^\s*[-*] ", b)])
fail if blocks > 1
```

No numeric threshold beyond the `1.4x` ratio for check (2); checks (1)/(3) are pure presence/count.

**Real-data breakdown, 7 held pieces across 3 weeks:**
- **6/7 fail check (1)** "no one-sentence paragraph found" — the dominant failure mode, every week.
- **3/7 also/only fail check (2)** "no section is notably longer than the others".
- **0/7 ever fail check (3)** — the bulleted-list cap has never actually fired in real production
  data; not a live problem.

**Root cause — genuine writer-prompt gap, but a subtler one than "no instruction exists" (evidence
below rules out the naive read):**
- `research.py::_VARIANCE_DIRECTIVES` (lines 50-55) **does** literally spell out all 3 rules:
  `"include ≥1 one-sentence paragraph"`, `"make one section notably longer than the others"`,
  `"≤1 bulleted list in the whole article"` — these ARE threaded into every draft call via
  `Brief.variance_directives` → `generation.py::_build_batch_prompt()`'s
  `"VARIANCE DIRECTIVES (apply across the whole piece): ..."` line (`generation.py:182`). So Q1's
  known-instruction claim is correct — the instruction exists.
- The gap is structural, not textual: `generate_draft()` drafts sections in **batches of 2-3, each a
  separate, independent Sonnet call** (`_batch_sections()`, target=3) that **never see each other's
  output**. A whole-piece constraint ("exactly ONE section should end up notably longer than the
  rest", "at least one short paragraph should exist SOMEWHERE across the whole piece") is repeated
  **identically and unconditionally to every batch**, with no signal about what earlier/other batches
  already produced — so each batch call has no way to know whether the piece-level quota is already
  met, or whose job it is to be "the long section". This explains check (1)'s 6/7 failure rate (a
  directive with no accountability owner across ~2-3 independent calls is easy for every call to
  quietly skip) directly.
- Check (2) is worse than under-instructed — it's **actively unactionable by the writer** as coded:
  `words_per_section = max(words_mid // len(outline), 100)` (`generation.py:136`) computes ONE
  uniform per-section word target, used identically for **every** batch's `max_tokens` sizing
  (`generation.py:142`). No section is ever told "you are the long one" — the length-variance
  directive and the uniform per-section token budget directly contradict each other in the code, not
  just in prompt wording.
- Check (3) never firing in real data is consistent with a single directive line being sufficient
  when the constraint doesn't depend on piece-wide coordination (avoiding a SECOND bulleted list is a
  per-batch-local decision each call can independently satisfy — no cross-batch coordination
  needed, unlike (1)/(2)).
- **Conclusion: (b) — prompt has the instruction, but it's structurally undeliverable for a
  piece-wide constraint under a batched, uncoordinated multi-call writer**, not (a) missing or (c) a
  gate/threshold bug. The 1.4x ratio and one-sentence-paragraph definitions themselves are not shown
  to be wrong by anything in the real data — every held piece's own paragraphs (AA-405's manual read)
  are genuinely uniform 3-7 sentences, not near-miss counts a looser threshold would have passed.

`FACT_CHECK_MANUAL_CHECK`. The judge (Nova Pro, temperature=0) always receives the FULL

**F9-social is the single largest failure mode: 15/33 pieces (45%), never zero in any of the 3 real
weeks (4→5→6).** Channel split is lopsided: **11/15 (73%) are tiktok**, only 4/15 facebook — tiktok

**Repair convergence — pulled all 15 pieces' real `repair_log` (3 rounds each). Confirms AA-405's
"never converges" claim with concrete quotes, now across all 3 weeks, not just week=2:**

Every single held piece shows a **different specific phrase** flagged as `GENERIC_AI_WORDING`/
`SUMMARY_OFF_BRAND` on each of its 3 repair rounds — never the same complaint twice. Concrete example
(`de8337ba...:slot_845eb6ec83cdf1f082ec:blog#tiktok`, week=1):
- round 1: flagged `SUMMARY_OFF_BRAND, CTA_MISSING_OR_WEAK` — "lacks a clear call to action."
- round 2 (after repair added a CTA): flagged `SUMMARY_OFF_BRAND, GENERIC_AI_WORDING` — quotes a new
  sentence as generic, AND says the phrase **"Design This Journey" itself "feels somewhat generic
  and not sufficiently unique"** — i.e. the judge penalized the literal brand-mandated CTA phrase
  (`brand_standards.py:12` requires exactly this phrase) as off-brand.
- round 3 (after a further rewrite): flagged `SUMMARY_OFF_BRAND, GENERIC_AI_WORDING` again, quoting
  yet a third, different sentence ("still forming its identity", "long ago settled into its own").

This pattern repeats identically across all 15 pieces — three different targets, three different
"generic" quotes, in every case. Several of the quoted "generic AI wording" examples read as
reasonably specific, crafted prose (e.g. `"the terrain does its own work"`, `"earns its arrival"`,
`"that contrast is precisely what this journey is designed to deliver"`) — not the templated
AI-tell phrases F2's fixed lexicon already catches (`nestled`, `hidden gem`, `breathtaking`, etc.).

**Root cause — genuinely mixed, both prompt AND rubric-side, evidence for both:**
- **(b) prompt-side, confirmed:** `adapt.py`'s `_FACEBOOK_INSTRUCTIONS`/`_TIKTOK_INSTRUCTIONS`
  inherit the shared `AA_BRAND_IDENTITY_PROMPT` block (so the REQUIRED/FORBIDDEN lexicon text IS
  technically present in every adapt call — `adapt.py:64`), but neither instruction explicitly
  requires working a REQUIRED-lexicon word (Design/Curated/Refined/Tailored/Journey) into the tight
  50-120 (facebook) / 100-150-"spoken/conversational" (tiktok) word budget, nor explains what
  "generic AI wording" means in a way the writer could self-avoid. The tiktok instruction's own
  explicit "spoken, conversational" register (`adapt.py:90`) is in real tension with the brand
  rubric's "calm, assured, curated, composed, premium, controlled" bar, and nothing in the prompt
  tells the writer how to reconcile the two — this maps directly to why tiktok fails ~3x more often
  than facebook in the real data.
- **(c) gate/rubric-side, real concern, not just a prompt gap:** `GENERIC_AI_WORDING`/
  `SUMMARY_OFF_BRAND` have no deterministic anchor (unlike F2's fixed regex lexicon) — they are Nova
  Pro's own subjective "does this sound premium enough" judgment, re-evaluated fresh each round
  against newly-repaired text with no memory of what it flagged last time. A rubric whose target
  moves round to round for what's really one underlying "vibe" complaint is close to unsatisfiable by
  any single prompt fix — `AA-372.md`'s own STEP 0 doc already flagged this rubric was built without
  real FB/TikTok data to calibrate against ("don't guess ahead of data" — line ~90-98); this session's
  3 real weeks are the first real calibration data, and they show the vocabulary/threshold itself,
  not just the writer prompt, is likely under-specified.
- Net: **predominantly (b)**, with a **real, evidenced (c)** layered on top — a pure writer-prompt
  fix (require 1 lexicon word, reconcile "conversational" vs "premium") should reduce this
  substantially given the concrete gaps found, but is unlikely to fully converge repair rounds to
  zero without also tightening what `GENERIC_AI_WORDING` is allowed to mean (e.g., requiring the
  judge to quote why a SPECIFIC prior-round complaint was or wasn't addressed, or narrowing
  `GENERIC_AI_WORDING` to a smaller, checkable definition).

## Implementation — 15/08/2026 (branch `pqnghiep1354/aa-404-writer-prompt-f3-f8-f9`)

Built directly on STEP 0's conclusions above — no new recon, no re-reading. 4 parts, each fixing
exactly the mechanism STEP 0 pinned as root cause, nothing broader.

### Decisions

- **Part 1 (F3)**: chose "most atoms = long-section owner, fewest atoms = short-paragraph owner"
  over a random assignment. Deterministic and reproducible for a given Brief (same outline always
  gets the same assignment — easier to debug a held piece later), and the section with the most
  material is the natural fit for "develop this one in more depth" rather than an arbitrary pick.
  Ties break by outline order (Python's `max`/`min` keep first-encountered), not by hashing/random.
- **Part 1**: the length-redistribution multiplier is 1.7x, not the gate's bare 1.4x minimum — margin
  for real writer variance (the model won't hit an exact word target), so a real draft that lands
  short of its 1.7x target by some percent should still clear the 1.4x gate threshold.
- **Part 2 (F8)**: the ceiling is enforced at the DATA layer (`_select_atoms_for_channel()` in
  `adapt.py`, called before the prompt is even built), not only as prompt wording — matches the
  issue's explicit preference ("ưu tiên sửa ở tầng data ... nếu code cho phép"). tiktok is
  deliberately untouched (hook_beats_payoff has no single-atom constraint, and STEP 0 found zero
  real F8 failures on tiktok).
- **Part 3 (F8/AIDA)**: scoped to AIDA only, per the issue text ("khi framework=AIDA"). hub/PAS have
  the identical bare-label gap by inspection but zero real failures so far — flagged below as a
  follow-up rather than fixed here (Mistake-to-Rule, ADR-2026-009 — same stance already applied to
  F9-social's original build).
- **Part 4b (F9 rubric)**: added a `flagged_phrases` evidence field to the judge contract (mirrors F8's
  existing "every score of 1 needs a quoted evidence" pattern, `gate_framework()`) rather than trying
  to string-match free-text `notes`. The allowlist only fires when the CTA phrase is the SOLE quoted
  evidence for `SUMMARY_OFF_BRAND`/`GENERIC_AI_WORDING` — a CTA-phrase quote alongside a different
  real complaint, or any other failure code (`CTA_MISSING_OR_WEAK`, `HOOK_WEAK`), is left untouched.

### Changed

- `services/acp_produce/generation.py` — `generate_draft()`/`_build_batch_prompt()` now take a
  per-section `words_per_section: dict[str, int]` and `extra_directives: dict[str, list[str]]`
  (computed once per piece by new helpers `_select_variance_owners()`, `_compute_words_per_section()`,
  `_build_extra_section_directives()`) instead of one uniform word target and one blanket directive
  line. AIDA framework guidance (`_AIDA_FRAMEWORK_GUIDANCE`) and positional
  attention-hook/single-CTA notes added when `brief.framework == "AIDA"`. The old blanket
  `VARIANCE DIRECTIVES` line is kept as-is (still true, still useful for the non-gate-enforced "vary
  H2 rhythm" directive) — the new targeted notes are additive, not a replacement.
- `services/acp_produce/adapt.py` — new `_select_atoms_for_channel()` restricts facebook to its
  first-cited atom only (tiktok unchanged); `_FACEBOOK_INSTRUCTIONS` states the single-atom
  constraint explicitly; `_ADAPT_SYSTEM_PROMPT_BASE` requires at least one REQUIRED-lexicon word even
  under the tight word budget; `_TIKTOK_INSTRUCTIONS` reconciles "spoken/conversational" with the
  brand's premium register.
- `services/acp_produce/gates.py` — `gate_brand_seo_audit_social()`'s judge contract gained
  `flagged_phrases`; response parsing drops `SUMMARY_OFF_BRAND`/`GENERIC_AI_WORDING` (and upgrades
  `flagged` → `pass` if nothing else remains) only when every quoted phrase is the brand CTA phrase.
- Tests: `tests/unit/test_aa370_generation.py` (+16), `tests/unit/test_aa371_adapt_faq.py` (+4, plus 1
  existing test split into 2 to reflect the new facebook/tiktok asymmetry), `tests/unit/
  test_aa372_gates.py` (+4). Full suite: 1235 passed (was 1213 pre-AA-404), 0 regressions, flake8
  clean.

### Tradeoffs

- Part 1's word-count redistribution changes `generate_draft()`'s per-batch `max_tokens` sizing (now
  summed from the per-section dict instead of one uniform value) — verified this still respects
  `_MIN_MAX_TOKENS`/`_MAX_MAX_TOKENS` and that the total redistributed word budget stays within
  F4_brief_compliance's ±30% tolerance (unit test), but the actual real-world word-count drift can
  only be confirmed against a real Sonnet call, not a mock.
- Part 3 leaves hub/PAS with the same bare-framework-label gap Part 3 fixes for AIDA — a known,
  intentionally deferred gap, not an oversight (see Decisions above).
- Part 4b is a genuine change to F9-social's evaluation criteria, not just a prompt tweak — flagged as
  the highest-risk part of this PR (see PR description). The rubric's `GENERIC_AI_WORDING`/
  `SUMMARY_OFF_BRAND` codes are otherwise untouched; this only prevents one specific, real,
  confirmed false-positive shape (the brand's own mandated CTA phrase getting flagged as generic).
  It does not address the broader "moving target" non-convergence STEP 0 documented — that's a
  bigger rubric-calibration conversation with Ms. Thu (17/08), out of scope here.

### Should know

- None of this was verified against a real Bedrock/Nova Pro call — all tests mock `invoke_claude`/
  `invoke_judge`. The real test is Nghiep's post-merge N7 week=4 run (see PR description) — the
  writer/judge might still not follow the new instructions reliably even though the mechanism is
  now sound (deterministic ownership, data-layer ceiling, evidence-gated allowlist).
- Part 4b's `flagged_phrases` field is new — a judge response that doesn't populate it (older
  behavior, or a model that ignores the instruction) fails closed exactly as before this change
  (verified: `test_f9_social_no_allowlist_when_flagged_phrases_missing`), never silently passes.
