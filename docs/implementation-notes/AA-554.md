## Tradeoffs

- **Cross-filter fetch limit (200, capped by backend `Query(50, ge=1, le=200)`) vs. a real
  backend `segment_id`/`route_id` filter param.** A real filter would scale better as data grows
  well past 200 raw rows; chose the client-side approach because it needed no backend change for
  a UI-scoped build task, and today's real data (138 Segment rows, 6 Route rows) fits comfortably
  under the 200 cap. Flagging as real tech debt: if Segment's raw row count crosses ~200, this
  cross-nav can start silently missing targets again exactly like the bug below — worth a real
  backend filter param at that point.
- **Tours sidebar "Load more" is client-side windowing over an already-fully-loaded list**, not
  true backend pagination — `GET /admin/atoms/summary` already returns every tour's summary in one
  response (no `limit`/`offset` on `by_tour`). Adding real backend pagination there was out of
  scope for a UI-only build; the client-side window still satisfies the ask ("thêm phân trang kiểu
  Load more") without a backend change.
