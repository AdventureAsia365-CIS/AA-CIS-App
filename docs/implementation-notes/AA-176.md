# AA-176 — [DEPLOY-01] Immutable tags + ECS/Lambda safe rollout

## Decisions
- **Built only the ECS deployment circuit breaker (scope item 2), NOT the image-tag change
  (scope item 1) or Lambda CodeDeploy canary (scope item 3).**
- **Scope item 1 (immutable tags, `:latest` → git SHA) deliberately NOT built.** STEP0 found
  this issue's core premise directly contradicts a current, explicit, standing convention in
  `AA-CIS-App`'s own `CLAUDE.md`: `## CI/CD — Image tag: always :latest (never commit hash)`.
  Per this session's own operating instructions, project `CLAUDE.md` conventions override
  default behavior and are followed exactly as written — a 2-month-old backlog issue asking to
  reverse a since-established, explicit repo rule is a real conflict that needs Nghiệp's
  explicit decision, not something to silently override either direction. Flagged, not built.
- **Scope item 3 (Lambda alias + CodeDeploy canary) also not built this round** — entangled
  with the same tag-strategy question in spirit (versioned artifacts + traffic shifting), and
  a genuinely separate, larger unit of work on its own; left for a dedicated follow-up once
  the tag-strategy question (item 1) is resolved, since building canary/traffic-shift infra
  around a deploy pattern that might still change underneath it risks rework.
- **Circuit breaker IS safe and independent of the tag question** — `deploymentCircuitBreaker`
  triggers on deployment HEALTH (new tasks failing to stabilize/pass health checks), not on
  which tag scheme produced the failing task — genuinely orthogonal, real, low-risk value on
  its own. Built via Terraform (AA-CIS-Infra), per Nghiệp's own standing IaC-first convention
  (explicitly cited in AA-256's own comment thread re: `AA-Bedrock-Invoker` tech debt).

  last stable task definition revision instead of sitting in a broken, unnoticed state
  indefinitely.
