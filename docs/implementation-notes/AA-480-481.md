Companion to AA-477 (migration 121). All 3 (121, 122, and the AA-480 skill FK reference) build on
`docs/claude_audit/AA-479-schema-audit.md`'s findings — see that doc for the full evidence trail.

## Decisions
- Migration 122 kept as a SEPARATE file from 121, not merged into it — 121 already has an
  explicit go-ahead history (2 rounds of STEP0 + acp_output_rules re-check) and its own audit
  trail; keeping it untouched preserves that record. 122 documents AA-481's own, independent
  0-FK/0-caller evidence. Both are meant to run together (same PR, likely same apply session),
  but stay 2 migration version numbers for a clean audit trail.
- `test_all_29_lessons_in_registry` (tests/integration/test_validation_integration.py) removed —
  NOT one of the 7 files named in the task's Part B scope (it doesn't import services.acp.s2 at
  all), but found during verification: it INSERTs into shared.lessons_registry as part of a real
  Postgres integration test. CI's "Integration Tests" job spins up a genuine postgres:15
  container and replays every api/migrations/*.sql file via tests/integration/conftest.py — so
  once migration 122 merges, this specific test would go from "sandbox can't reach any DB"
  (this session's false-negative "0 new failures" diff) to a REAL failure in CI's actual
  Postgres run ("relation shared.lessons_registry does not exist"). Fixed proactively rather than
  left for CI to catch, since it's a direct, predictable consequence of code in this same PR.
- Swept tests/integration/ specifically (the only test dir CI runs against a real live Postgres)
  for references to all 21 tables being dropped, not just the 7 named files — found only the
  1 additional case above, plus the already-understood tests/integration/conftest.py stub for
  acp_shared.acp_runs (verified safe in AA-477 — DROP TABLE IF EXISTS on a schema/table that
  doesn't exist is a no-op in Postgres, and the stub's own comment already documents it's only
  needed up to migration 096, long before 121/122).
