# AA-539 — Install mattpocock/skills + official CONTEXT.md glossary

## Decisions

- **Single root `CONTEXT.md`, not a multi-context map.** The issue's own term list (Atom/
  Segment/Score/Route/Hub/Slate/Subject/Facts Entry/A-series/T-series) is all one connected
  domain (Master Content → Tenant content pipeline). Other subsystems (Excel ingestion, LLM/
  model routing, marketplace/billing, legacy N0-N8) were left out rather than force-fit into the
  same glossary — a `CONTEXT-MAP.md` can be added later if those need their own.
- **Included Goal/Angle/Gate/Piece/Channel beyond the issue's literal list.** These are real,
  already-in-use domain nouns (not generic programming terms) that the requested terms don't
  make sense without — a glossary that defines Slate/Subject but not Goal/Angle would be
  incomplete for its stated purpose (preparing for the UI epic).
- **Wrote exactly one ADR (`docs/adr/0001-...md`), not a batch backfilling every past decision.**
  domain-modeling's own rule is "only when hard-to-reverse + surprising + a real trade-off, all
  three." Evaluated several candidate past decisions (ADR-2026-038 Hướng B, the AA-511 Slate
  port, AA-501's review screen) — none met all three well enough to write today; the one that
  did (atoms platform-wide vs. Segment/Score/Route per-tenant) is also the one directly
  responsible for this task's biggest finding (see Should know).
- **Did not fix the AA-526-vs-AA-539 contradiction myself.** Per domain-modeling's own rule
  ("call it out immediately," not "silently resolve it") and the issue's explicit "không thuộc
  scope: không tự động build gì" — flagged as CONTEXT.md's Open Question 1 and this issue's own
  comment, left for Nghiệp/the `/grill-with-docs` pass on the UI epic spec to settle.

## Changed

- Installed `mattpocock/skills` (37 skills total, including all 4 named in the issue) via
  `npx skills add mattpocock/skills` — real content in `.agents/skills/`, symlinked into
  `.claude/skills/` (Claude Code's own skill directory), `skills-lock.json` records the exact
  commit/hash per skill.
- New `CONTEXT.md` (repo root) — full glossary, grounded in real code/schema reads, not just
  restated issue prose (see Should know for the sources).
- New `docs/adr/0001-atoms-platform-wide-segments-per-tenant.md`.
- New section in `.claude/CLAUDE.md` ("Domain Model / Architecture Process") per the issue's
  06/09 addendum comment.

## Tradeoffs

- `.agents/skills/` (824K, 100 files) is committed to the repo rather than left as a local-only
  install, so every session/teammate gets the same skills without re-running the installer —
  costs repo size, but a `.gitignore`'d skill directory would silently diverge between sessions
  (exactly the kind of untracked-process gap AA-539 exists to close).
- `CONTEXT.md` currently only covers the content-pipeline domain, not the whole codebase. A
  reader looking for Excel-parser or LLM-routing vocabulary won't find it here yet — acceptable
  given the issue's own scope (preparing for the Admin/Tenant UI epic specifically), but should
  not be read as "the only domain that matters."
