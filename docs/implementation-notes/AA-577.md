# AA-577 — Gate Swagger UI/ReDoc/openapi.json behind X-Admin-Secret in production

## Decisions
- **Not gated on `ENVIRONMENT`.** STEP0 found Terraform sets `environment = "dev"` for the ONE
  real AWS deployment this app has (`aws ecs list-clusters` → only `aa-cis-dev-cluster`, no
  separate staging/prod cluster exists) — confirmed live on the running ECS task
  (`ENVIRONMENT=dev`). Gating on `ENVIRONMENT == "production"` would never be true and would
  leave Swagger fully exposed — exactly the opposite of this fix.
- **Gated on `AWS_EXECUTION_ENV` instead** (`_is_publicly_deployed()`, `api/main.py`) — an
  AWS-injected env var present on every real ECS/Fargate task (confirmed live:
  `AWS_EXECUTION_ENV=AWS_ECS_FARGATE`) and absent on a local machine and on GitHub Actions CI. No
  Terraform change needed, and it can't be spoofed by an unauthenticated request (read only from
  the process's own environment).
- Reused the existing `verify_admin_secret()` (`api/routers/admin.py`) rather than writing a
  second admin-secret check — same header, same 503 (secret not configured)/403 (wrong secret)
  behavior every `/admin/*` route already has.
- All 4 routes named in the issue (`/docs`, `/redoc`, `/openapi.json`, `/docs/oauth2-redirect`)
  gated the same way, behind one shared dependency — the issue's own point #3 ("blocking the UI
  but leaking the JSON source is pointless") applies symmetrically to all 4, not just `/docs`.

## Changed
- `api/main.py`: `FastAPI(...)` gains `docs_url=None, redoc_url=None, openapi_url=None` (disables
  the auto-registered, unprotected copies); `/docs`, `/redoc`, `/openapi.json`,
  `/docs/oauth2-redirect` re-registered by hand using FastAPI's own `get_swagger_ui_html()`/
  `get_redoc_html()`/`get_swagger_ui_oauth2_redirect_html()`/`app.openapi()`, each behind
  `require_admin_secret_for_docs()`.
- `tests/unit/test_aa577_swagger_docs_gate.py` (new): `_is_publicly_deployed()`,
  `require_admin_secret_for_docs()` (local/CI no-op vs. deployed 403/pass), and a regression
  check that all 4 routes are both disabled-by-default and re-registered with the gate attached.

## Tradeoffs
- None of significance — this is a straightforward, standard FastAPI pattern for protecting the
  built-in docs routes.

## Should know
- Local dev and CI are completely unaffected by design (`_is_publicly_deployed()` returns
  `False` for both) — Swagger stays open there, per Nghiệp's explicit decision.
- If AA-CIS-App ever gets a real separate staging/prod split (unlike today's single "dev"
  cluster), `_is_publicly_deployed()` would need revisiting — it currently treats "real AWS
  deployment" and "the thing that needs protecting" as the same thing, which is true today but
  wouldn't be once a real internal-only staging environment exists.
