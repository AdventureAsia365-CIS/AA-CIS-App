## Decisions

- **Việc 3 scope**: "Quarter Plan UI cũ" read narrowly as the Preview/Trip-table/Finalize/History
  block in `PlanningTab.tsx` only. `FeedbackSection`/`ReallocationSection` (round-6 extensions,
  own card headings, don't reference the removed trip-selection UI directly) are kept — flagged
  explicitly in the wireframe comment as a scope call Nghiệp can correct.
- **Việc 2 Route badge**: informational only (`Badge variant="gold"`, not a clickable link) — no
  tenant-facing single-Route detail page exists yet (Route is only visible through T7's Slate).
- **Việc 4 schema**: 2 new nullable `content_piece` columns (`route_hub_name`, `route_segment_count`)
  set once at INSERT (immutable across T9's internal retry loop, unlike `content_text`/
  `gate_ledger`). Not threaded into `admin_a4.py`'s AA-internal content-log — out of explicit
  scope (issue only asks for T9→T10→T11, tenant-facing).
- **Việc 5 mechanism**: new `blocking: bool` field on `GateResultLite`, defaulting to `True` via
  `_result()`'s own signature default — every existing gate call site (F1/F2/F3/F4/F6/F7/F8/F9)
  needs zero changes, only `gate_promises_an_option()` passes `blocking=False`. `first_failure`
  (which drives hold/repair in `service.py`) only considers `blocking=True` gates now. A new
  `flags` list (failed-but-non-blocking gates) is a NEW `content_piece.flags` jsonb column,
  deliberately separate from `gate_ledger` — safe to expose to the tenant (unlike the full
  ledger, which STEP0 §4 of AA-501 kept admin-only) since it only ever holds "note for a human"
  gates, never the 8 unaffected hard gates' detail.
