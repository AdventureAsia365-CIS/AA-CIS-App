# AA-472 — Remove mandatory portfolio/angle from tenant onboarding (Hướng B)

## Decisions

- **Hướng B over Hướng A** (ADR-2026-038): a new tenant's tour/atom selection is made live by the
  tenant itself via `GET /v1/marketplace` (AA-444), not curated in advance by staff via a
  finalized `acp_shared.marketplace_portfolios` row. Nghiep's call, made explicit before any code
  changed.
- **Scope expanded 3 times over the course of this task, in this order** — each expansion driven
  by a real finding, not speculative gold-plating:
  1. **Round 1 (STEP0)**: scope was "make `portfolio_id` optional" — `ALTER COLUMN ... DROP NOT
     NULL`, `seed_tenant_atoms()` gets an `Optional[UUID]` body field. STEP0 recon (grepping
     `portfolio_id`/`marketplace_portfolios`) surfaced that `frontend/app/admin/tenants/page.tsx`
     had a whole wizard *step* gating on portfolio_id being required, not just a backend field —
     confirmed with Nghiep before touching code.
  2. **Round 2**: Nghiep changed the ask mid-flight to "remove hoàn toàn" — delete
     `seed_tenant_atoms()`, `/admin/marketplace` (backend `admin_marketplace.py` + frontend page),
     not just relax the constraint. Reason given: portfolio seeding was never actually required by
     the real product flow (Hướng B), so an optional field would have kept dead UI/API surface
     alive for no reason.
  3. **Round 3 (mid-implementation, this task's own real bug)**: while wiring the frontend for the
     round-2 deletion, tracing `seed_tenant_atoms()`'s full body (not just the part matching the
     task's own vocabulary) showed it did **two** inserts — `tenant_onboarding` (portfolio
     pointer) **and** `acp_shared.tenant_atom_state` (the tour list + `assigned_angle` column).
     Migrating only the first insert into `create_tenant()` left `tenant_atom_state` permanently
     empty for every tenant created from then on, which silently breaks 3 other endpoints that all
     hard-require ≥1 row in it (see **Should know** below for the full trace). Reported to Nghiep
     as a blocking finding rather than patched around; Nghiep's resolution: angle was modeled wrong
     from the start (AA-309) — it's a per-*piece* (T8) attribute, not a per-*tenant* one — so the
     fix was to delete the angle/Mirror concept from N1 entirely, not invent a workaround to keep
     `tenant_atom_state` populated.
- FK `tenant_onboarding_portfolio_id_fkey` (real name, confirmed via `pg_constraint` on RDS, not
  guessed) is **kept**, only `NOT NULL` dropped — legacy tenants onboarded before this change keep
  a real, valid `portfolio_id`; no new tenant will ever populate it again.
- `create_tenant()` inserts the `tenant_onboarding` row itself, in the same transaction as the
  tenant row, always with `portfolio_id=NULL` — Gate A approval no longer depends on any separate
  step happening first, closing the exact gap `seed_tenant_atoms()` used to exist for.
- `get_gate_a_status()`'s defensive "no row" 404 is **kept** (unlike `approve_gate_a()`'s, which
  was removed outright) — it's a GET status-check endpoint with no transactional guarantee tying
  it to `create_tenant()`, so the check stays as a real defensive branch, only its stale
  "run seed-atoms first" message text was fixed.

## Changed

- **Migration 119** (`api/migrations/119_tenant_onboarding_portfolio_optional.sql`):
  `acp_shared.tenant_onboarding.portfolio_id DROP NOT NULL`. FK unchanged.
- **Deleted entirely**: `seed_tenant_atoms()` + `SeedAtomsRequest` (`POST
  /admin/tenants/{id}/seed-atoms`), `assign_tenant_angle()` + `AssignAngleRequest` (`PATCH
  /admin/tenants/{id}/angle`), `get_tenant_mirror()` (`GET /admin/tenants/{id}/mirror`),
  `api/routers/admin_marketplace.py` (whole file — no caller left after `seed_tenant_atoms()` was
  removed), `ASSIGNED_ANGLES` dict (`api/routers/admin.py`), `frontend/app/admin/marketplace/`
  (whole directory).
- **`api/main.py`**: removed the `admin_marketplace_router` import + `include_router` call.
- **`create_tenant()`**: now inserts `tenant_onboarding (tenant_id, portfolio_id)` with
  `portfolio_id=NULL` right after the audit-log insert, same transaction.
- **`approve_gate_a()`**: removed the `has_angle` check (`SELECT ... tenant_atom_state ...
  assigned_angle IS NOT NULL`) entirely — `approval_status == 'pending'` is now the only real
  precondition. Also removed the "no tenant_onboarding row → 404" branch (dead code now that
  `create_tenant()` guarantees the row unconditionally).
- **`list_tenants()`**: `pending_tenants[].onboarding` no longer carries `seeded`/
  `seeded_tour_count`/`angle_assigned` — the underlying `LEFT JOIN acp_shared.tenant_atom_state`
  (and its `GROUP BY`/aggregate columns) was dropped along with them. Only `gate_a_status` remains.
- **Frontend** (`frontend/app/admin/tenants/page.tsx`): `OnboardingTabContent` reduced from 4
  steps (Seed Atoms → Assign Angle → Mirror pointer → Gate A approve) to 1 (Gate A approve only).
  `MirrorTabContent`/`MirrorData` deleted outright (backend route gone). `mirror` removed from the
  `DTab` union and the tab bar. `pendingStep()` → `pendingStepLabel()` (no more "Step X of 3"
  since there's only one step left). Dead imports cleaned up (`Lock`, `Sparkles` icons,
  `ASSIGNED_ANGLES` const).
- **`frontend/app/admin/_components/AdminSidebar.tsx`**: removed the "Marketplace" nav item +
  unused `ShoppingBag` import.
- **`frontend/middleware.ts`**: removed the `/admin/marketplace` `PROTECTED_ROUTES` entry.
- **Tests**: `tests/unit/test_aa330_admin_marketplace.py` deleted outright (tested the deleted
  router). `tests/unit/test_aa309_tenant_onboarding.py`: removed `TestConstants`, `TestSeedAtoms`,
  `TestAssignAngle`, `TestMirror` classes; removed `TestGateAApprove`'s
  `test_no_onboarding_row_404` and `test_no_angle_assigned_rejected_400`; updated
  `TestListTenantsPending`'s two tests to match the new `{"gate_a_status": ...}`-only response
  shape.

## Tradeoffs

- **No API path left to manually assign a tenant a starting tour list at onboarding time.** A
  brand-new tenant's only route to content is `GET /v1/marketplace` after they're active — there
  is deliberately no admin-side "give this tenant N tours to start with" step anymore. Accepted
  because this is exactly Hướng B's intent (ADR-2026-038): the platform doesn't pre-select
  anything for a tenant, the tenant self-serves.
- `acp_shared.tenant_atom_state` is now write-orphaned going forward (no code inserts into it for
  any tenant onboarded after this change) — the table and its `assigned_angle` column are not
  dropped, since legacy tenants (onboarded before AA-472) still have real rows there and nothing
  in this task required a data migration/backfill. Left as-is; a future cleanup task could drop it
  once the legacy rows are confirmed unread by anything else.
- `services/acp_shared/marketplace_estimates.py` (`parse_price`/`runway_months`) was **not**
  deleted despite becoming unused in `admin.py` — it's still a real, live dependency of
  `api/routers/v1_marketplace.py` (confirmed via grep before touching anything), so only the
  now-unused import in `admin.py` was removed, not the module itself.

## Should know

- **The round-3 bug, in full, for anyone doing a similar "delete a function" migration**:
  `seed_tenant_atoms()` was one function with two `INSERT`s — `tenant_onboarding` (what the task
  vocabulary was about) and `tenant_atom_state` (not mentioned anywhere in the original ask).
  Migrating only the first insert into `create_tenant()` *looked* complete against the literal
  task description, but silently broke three other endpoints that all hard-depend on
  `tenant_atom_state` having ≥1 row: `assign_tenant_angle()` (404 "0 rows updated"),
  `get_tenant_mirror()` (404 "no state rows"), and `approve_gate_a()`'s own `has_angle` check (400
  forever — no angle could ever be set on a table with zero rows). Net effect: Gate A could never
  approve a tenant created after the naive fix. Caught by re-reading the full function body and
  tracing every table it touched (not just the one the task named) before declaring the migration
  done — see memory `feedback_check_all_callers_before_deleting_shared_function` for the general
  lesson.
- If a future task references N1 onboarding, Gate A, "Mirror", or tenant-level "angle" — none of
  those concepts exist anymore post-AA-472. `GET /admin/tenants/{id}/gate-a/status` is the only
  onboarding-progress read left; `pending_tenants[].onboarding` only carries `gate_a_status`.
- `acp_contract.tour_atoms.owner_scope`, `angle_gate_request`/`angle_gate_option` (T8's real
  per-piece angle concept, migration 113) are **unrelated** to the deleted
  `tenant_atom_state.assigned_angle` — do not confuse the two when reading older AA-309/AA-330
  history in this file's own git blame.
