## Việc 2 — sticky footer/toolbar

Changed: `frontend/app/admin/marketplace/page.tsx`

- Moved `<PortfolioBar />` + `{portfolio && <PortfolioResult />}` out of the scrollable `<main>`
  and into a new sibling `<div>` (after `</main>`, still inside the right-column flex container),
  styled `position: "sticky", bottom: 0, zIndex: 10, background: A.bg, borderTop: 1px solid A.line,
  padding: "16px 36px", boxShadow: "0 -2px 8px rgba(0,0,0,0.04)"`.
- This mirrors the exact mechanism the page's own `<header>` already uses for the top bar
  (`position: "sticky", top: 0, zIndex: 10`) — same pattern AdminSidebar.tsx uses for the left nav
  (`position: "sticky", top: 0, height: "100vh"`). All three rely on document-level scroll: the
  outer wrapper is `minHeight: "100vh"` (a floor, not a cap), so when content is taller than the
  viewport the row grows past 100vh instead of clipping — `<main>`'s own `overflowY: "auto"` never
  actually engages (its box always equals its content height, nothing to internally scroll), so the
  *document* scrolls, and `position: sticky` on both header and this new footer pins to the
  viewport edge exactly as already observed on the header.
- `PortfolioResult` is rendered directly under `PortfolioBar` inside the same sticky block (not
  reordered), so "kết quả portfolio ngay dưới toolbar" holds.
- Removed `marginTop: 16` from `PortfolioBar`'s `Card` style (was for spacing when it sat inline in
  the scroll flow; the new wrapper's own `padding` replaces it). `PortfolioResult`'s `marginTop: 16`
  kept as-is — that's what spaces it from `PortfolioBar` above it inside the sticky block.
- Tour list/table itself: untouched, still scrolls normally inside `<main>`.
