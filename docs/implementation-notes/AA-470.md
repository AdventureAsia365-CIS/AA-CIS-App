# AA-470 — /goal missing `asyncio.to_thread()`, blocks ECS event loop

## Decisions

- Scope is exactly the 1-line gap STEP0 found: `services/acp_angle_gate/generate.py::generate_angles()`
  called `client.generate(request)` directly (synchronous `LLMClient.generate()`) inside an
  `async def`, never wrapped — every other blocking LLM call in this codebase (T9's `write_content`/
  `rewrite_with_feedback`/`run_quality_gates` in `services/acp_content_writing/service.py`, AA-416's
  N7 fix) already goes through `asyncio.to_thread()`. Fixed the same way, same pattern, no new
  abstraction — `resp = await asyncio.to_thread(client.generate, request)`.
- No change to `generate_angles()`'s signature, return shape, error handling, or logging — the fix
  is the wrap only.

## Changed

- `services/acp_angle_gate/generate.py`: added `import asyncio`; changed
  `resp = client.generate(request)` to `resp = await asyncio.to_thread(client.generate, request)`.

## Tradeoffs

- Runtime (post-deploy) verify — confirming `/health` stays fast while `/goal` runs on the FIXED
  code — was NOT done in this PR. Deliberate: this branch was never deployed (per the task's
  explicit "không tự merge" constraint), so there was no live ECS environment running the fix to
  test against. See "Live Verify" below for what WAS measured instead, and what still needs
  confirming after merge+deploy.
