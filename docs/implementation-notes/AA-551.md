# AA-551 — Split `/admin/atom-curation` (01-05 platform-wide) + new `/admin/tenant-activity` (06-08)

Source of truth: `docs/investigation/AA-550-admin-ui-real-audit.md` (AA-550, screenshots on that
Linear issue). Wireframe posted to AA-551 Linear comment before any code, per issue requirement.

## Decisions

- **Two pages, not one page with two zones** (Nghiệp's explicit choice, "Phương án B" over the
  audit's "Phương án A"). `/admin/atom-curation` keeps its URL/name; `/admin/tenant-activity` is
  new.
- **Slate (05) stays exactly as-is** — still requires a Tour, still per-tenant (`acp_shared.
  subject.tenant_id NOT NULL` is real schema, not a display bug) — explicitly out of the
  platform-wide scope per the issue's A.3. Only its `PickTourPrompt` copy moves to English.
- **Header stats via one new endpoint** (`GET /admin/dashboard/summary`) rather than deriving from
  each section's own `total` — the header must show all 6 numbers regardless of which section tab
  is open, and a client-side composition of 4 section fetches just to render a header would
  duplicate exactly the round-trip-multiplication problem the 401 investigation (see below) found
  in the first place.
- **"Hub" count is `COUNT(DISTINCT route.hub_name)`, not a real `acp_contract.hub` row count** —
  that table has 0 rows in production (already documented in `admin_dashboard.py`'s
  `hub_grouping_backlog` field, AA-527). Counting the empty real table would show a permanently
  misleading 0; the text-field proxy is what section 04 already renders. Documented inline in the
  endpoint's own docstring, not silently substituted.
- **Route/Hub version history differs by mode**: a single Tour selected keeps today's behavior
  (shows the FULL version history, current + superseded — AA-532's own deliberate audit-view
  choice, "not a bug"); "All tours" mode defaults to current-only (`superseded_at IS NULL`) to
  keep a platform-wide table from listing every historical version of every tour's routes at
  once. Not a toggle in this build — flagged as a possible follow-up, not built speculatively.
- **`BacklogNote` deleted, not translated** — A.5 of the issue explicitly asks to check whether
  this build resolves what the note flags (no admin UI for Hub grouping reasoning) before
  deciding to translate vs. remove. It doesn't (Hub grouping *reasoning* — "why these Routes
  share a Hub" — is still nowhere; only `hub_name` text and a derived count are shown) — but the
  Vietnamese paragraph itself named a stale line-number reference (`AA-525 Phần 12 mục 8`) with no
  new information a reader needs beyond "this is still a gap." Replaced with one short English
  line instead of a translated wall of text, per A.5's own "or xóa nếu nội dung đã lỗi thời" option.
- **401 fix bundled into this same PR** (not a separate one) — see Part B below; the issue allowed
  either, and the bug is directly triggered by this page's own concurrency shape.

## Tradeoffs

- Considered giving `/admin/dashboard/summary` its own market-aware `atom_count`; atoms have no
  `market` column at all (market is a property of `atom_ranking` rows, computed downstream of
  Atom), so `atom_count` only ever responds to the Tour filter, never Market — documented in the
  endpoint rather than faked.
- Considered a `show_superseded` toggle on the platform-wide Route/Hub table instead of a fixed
  current-only default; deferred — no UI ask for it in the issue, and adding a toggle "in case
  it's useful" is exactly the kind of speculative surface this repo's own conventions avoid.
- Considered fixing the 401 by raising the timeout instead of adding a cache; rejected — a longer
  timeout lowers the odds without removing the actual redundant-round-trip cause, and this page's
  own concurrency (~8 simultaneous `/api/admin/*` calls per Tour selection) is unusual enough that
  "less likely" isn't the same as "fixed."
