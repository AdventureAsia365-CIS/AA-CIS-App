# AA-379 — keyword_seed thật thay vì atom-text bị cắt

STEP 0 required source confirmation before any fix. Recon done live against dev DB (2026-08-07)
before touching `allocator.py`.

## STEP 0 findings

- **Bug, verbatim**: `services/acp_planning/allocator.py::make_slot()` set
  `keyword_seed=chosen[0].text[:60]` — an arbitrary char-index slice of a full sentence (e.g.
  `"Multi-day trek through the Yaksa region, with dedicated trekking days building up to a camp
  night."` → `"Multi-day trek through the Yaksa region, with dedicated t"`). Not a search phrase.
  `services/acp_produce/research.py::fetch_slot_demand_data()` sends this string verbatim to
  DataForSEO's `google_ads/search_volume/live` (exact-match lookup) — a garbled fragment
  legitimately matches nothing, `demand.volume=None, confidence="heuristic"`, and
  `compile_brief()`'s demand law then TOPIC REJECTS the slot (`no_demand_evidence`). This is what
  AA-375 attempt 2 hit live.
- **Candidate sources checked, live query against dev DB** (`acp_contract.v_trip_registry` floor
  = 763 trips):
  - `published_tours.seo_keywords_used` (real DataForSEO top_keywords, persisted at publish
    time): only 19/763 trips have a published_tours row at all, and only **7/763 (0.9%)** have a
    non-empty value. Too sparse to be a source — consistent with AA-316's own recon
    (`api/migrations/083_v_trip_registry_raw_tour_floor.sql`): only a small minority of the
    `v_trip_registry` floor ever gets a `published_tours` match.
  - `silver_aa_internal.seo_context` (legacy S1-S3 DataForSEO enrichment): only 36/763 trips
    (4.7%) have a row, though all 36 have non-empty `top_keywords`. Same sparsity problem.
  - `acp_contract.tour_atoms`: 602 live atoms across only 54/763 trips. Looks equally sparse in
    isolation, **but `compute_slot_grid()`/`make_slot()` can only ever build a Slot for a trip
    that has eligible atoms in the first place** (`if not pool: ... slot dropped`) — so the
    54-trip population is exactly the population that ever reaches `keyword_seed` construction.
    Within it: `activity_type` (the decompose LLM contract's required 7-value enum —
    trek/bike/food/culture/stay/transit/other) is **100% filled (602/602)**; `emotional_hook` is
    98.5% filled but free-text/evocative, not phrase-shaped.
  - `raw_tours.activities` (the field `seed_builder.build_seed()` was originally built for):
    199/763 (26%) non-null — richer than tour_atoms coverage-wise, but per-TRIP not per-atom, so
    using it alone would reintroduce B6 (same keyword shared by every slot of a trip).
- **Conclusion**: `activity_type` + `Trip.destination`, fed through the already-proven
  `services/seo_intelligence/seed_builder.build_seed()` convention (`"{activity} in {country}"`,
  AA-197/AA-251 — the same shape that already works against real DataForSEO traffic elsewhere in
  this repo), is the best available real source. Not fabricated: `activity_type` is a real,
  LLM-classified field already stored per atom; `build_seed()` is reused verbatim, not
  reimplemented.

## Decisions

- **Reused `seed_builder.build_seed()` instead of writing new seed logic.** It was built for
  `raw_tours.activities` (free text), and `activity_type` is a coarse 7-value enum — a repurposing
  of its "most specific" priority tier, not the identical continuation of AA-197's original intent.
  Flagged here rather than silently treated as the same thing.
- **`activity_type` added to the read path, not invented.** It already existed on
  `acp_contract.tour_atoms` (migration 079) and on the decompose LLM contract
  (`api/routers/v1_atoms.py`) but was never selected by `_ATOM_ROW_QUERY`
  (`services/acp_planning/quarter.py`) or modeled on `AtomRecord`. Added both.
- **campaign slots are NOT exempt from this fix.** `make_slot()` is a single shared function for
  both `kind="evergreen"` and `kind="campaign"` — there is no separate code path. Confirmed via
  grep: the only place `kind == "campaign"` matters downstream is
  `research.py::compile_brief()`'s demand-law gate (campaign slots are exempt from the
  no-demand-evidence reject, not from keyword_seed construction). The issue's instruction to leave
  campaign untouched "unless confirmed affected by the same bug" — it is structurally affected,
  so the fix necessarily applies to it too.
- **reactive_hold slots: no change, none needed.** They never carry `trip_id`/`atom_ids`
  (`make_slot()` returns early for `kind == "reactive_hold"` with `keyword_seed` left at its
  default `None`) — there is no atom to derive a keyword_seed from, by design (Mode-B not yet
  defined, unrelated to this issue).

## Changed

- `services/acp_planning/models.py` — `AtomRecord.activity_type: Optional[str] = None`.
- `services/acp_planning/quarter.py` — `_ATOM_ROW_QUERY` selects `ta.activity_type`;
  `_row_to_atom()` populates it.
- `services/acp_planning/allocator.py` — `make_slot()`: `keyword_seed` now built via
  `build_seed(country_raw=t.destination or "", activities=[top_atom.activity_type] if
  top_atom.activity_type else None, tour_name=t.name)` instead of `chosen[0].text[:60]`.
  `topic_hint` (`chosen[0].text[:80]`) is unchanged — not part of this bug (feeds prompt context,
  never sent to DataForSEO).
- Tests updated to reflect real atom shape (production atoms are 100% `activity_type`-filled, a
  required field of the decompose contract) rather than dodging the new field:
  `tests/unit/test_aa301_quarter.py` (3 mock rows gain `activity_type`),
  `tests/unit/test_aa300_admin_atoms.py` (`_atom_db_row` fixture gains `activity_type`),
  `tests/unit/test_aa301_allocator.py` (`_atoms()` fixture now cycles through the real 7-value
  enum instead of leaving it unset).

## Tradeoffs

- **Known, bounded collision risk, not solved here.** `activity_type` is only 7 buckets. Two
  slots for the same trip in the same month that land on atoms sharing the same `activity_type`
  will get an identical `keyword_seed` — narrower than pre-B6's full trip-wide sharing (which this
  fix does not regress: the existing `test_four_blog_slots_four_distinct_keyword_seeds` regression
  test still passes, because B7's atom-rotation plus the 7-value spread usually keeps `chosen[0]`
  distinct across a trip's slots in one month) but not zero. Flagged for Nghiep to decide whether
  it needs a follow-up (e.g. appending a cleaner per-atom qualifier) once real traffic shows
  whether it actually manifests.
- **Coverage stays bounded to the 54/763-trip atom population** — this fix does not expand which
  trips can produce a Slot at all (that gate is the pre-existing atom-floor check, unrelated to
  keyword_seed). It only fixes the keyword quality for trips that already clear that gate.
