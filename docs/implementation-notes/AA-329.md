# AA-329 (a)+(c) — day-count-mismatch validator + ITINERARY_STILL_COMPRESSED gate on S1-old

## Decisions

- **Not using `state["itinerary_day_ratios"]` for the gating check, despite the Linear comment
  thread (05/08, e2d68a35) proposing exactly that.** That field is set ONCE by `generate_node`'s
  `_process_itineraries` (AA-353) and never updated again. If `validate_node`'s new
  `ITINERARY_STILL_COMPRESSED` check read it directly, `revalidate_node`'s re-run of
  `validate_node` (after `flag_fix_node` repairs a day) would still see the STALE pre-fix ratio
  and re-fire the code even though the fix already succeeded — `revalidate_passed` would never
  flip to `True` for a tour this gate ever touched. Instead, both the day-count-mismatch check
  (a) and the still-compressed check (c) re-derive day word counts FRESH from the CURRENT
  `generated["itineraries"]` string (already normalized to canonical `"Day N — Title\nBody"` by
  the existing cleanup block earlier in `validate_node`) every time `validate_node` runs, compared
  against `tour["itineraries"]` (source, re-parsed via the same `parse_source_day_word_counts`
  `generate_node` already uses). This is self-correcting on revalidate for free, and is exactly
  equivalent to "still violating after nudge" on the FIRST validate_node call (since
  `_process_itineraries` already nudged once before validate_node ever runs) — so it doesn't
  change the intended semantics, only where the number comes from.
  `state["itinerary_day_ratios"]` / `metadata.itinerary_compression.still_violating_after_nudge`
  (admin_pipeline.py) are UNCHANGED — they stay as observability-only, matching the STEP 0
  instruction's own contingency ("nếu field không có sẵn trong state lúc validate_node thì phải
  sửa lại cách truyền state").
- **Extracted `ITINERARY_CLAMP_MIN/MAX` + `_nudge_itinerary_day` out of `graph.py` into a new
  `services/content_generation/itinerary_utils.py`.** `flag_fix_node.py` needs to call the same
  per-day nudge for `ITINERARY_STILL_COMPRESSED`, but `graph.py` already imports `flag_fix_node`
  — importing back would be circular. This is the exact same fix AA-205 used for `seo_meta`
  (`seo_meta_utils.py`, see its own docstring) — same pattern, new file. `graph.py` re-imports the
  same names so `from services.content_generation.graph import ITINERARY_CLAMP_MIN` (used by
  `admin_pipeline.py` and the AA-353 test file) keeps working unchanged.
- **`ITINERARY_STILL_COMPRESSED` added to `flag_fix_node._DETERMINISTIC_SEO_CODES`** (kept the
  existing name — it's imported by name in `tests/unit/test_aa204_meta_over_band.py` and
  `tests/unit/test_aa238_239_seo_meta_guard.py`, renaming would break both for a cosmetic gain).
  This is literally what the Linear comment proposed ("tương tự dòng 49-52").
- **Deduction sizes**: `ITINERARY_DAY_COUNT_MISMATCH` = `("structure", 1.0)`, same as
  `ITINERARY_STRUCTURE_WEAK` per the task's explicit instruction ("không tự nghĩ số ngẫu nhiên").
  `ITINERARY_STILL_COMPRESSED` = `("structure", 1.5)` — heavier (task said "đủ nặng"), but
  confirmed by hand that even 1.5 alone never drops `quality_score` below `MIN_QUALITY=7.0` (the
  4-dimension average dilutes any single-code deduction too much — same property the existing
  `_DETERMINISTIC_SEO_CODES` all share), so it can't accidentally divert the run to
  retry/hitl before ever reaching `flag_fix_node` — confirmed by reading `should_retry`.
- **`ITINERARY_STILL_COMPRESSED` bypasses the generic `FIX_SYSTEM` LLM-fix-all-fields prompt.**
  When it fires, `"itineraries"` is pulled OUT of the generic `fix_keys` set and repaired via a
  dedicated per-day path (`_repair_still_compressed_days`) that reuses `nudge_itinerary_day` with
  the correct `target_word_count` per violating day — the generic prompt (flag_fix_node.py
  FIX_SYSTEM path) has no idea what the target length is. If `ITINERARY_STILL_COMPRESSED` and
  another itinerary-touching code (e.g. brand_audit's `ITINERARY_MEAL_TIME_INVENTED`) fire in the
  same pass, only the dedicated path runs for itineraries (avoids two LLM calls editing the same
  field in conflicting ways in one pass).
- **Deterministic accept/reject guard on the flag_fix repair** (mirrors `best_meta_candidate`):
  a day is only overwritten if the second nudge attempt actually lands in-clamp; otherwise the
  pre-fix day text is kept untouched. No open-ended retry loop — one extra attempt per violating
  day, same single-shot budget AA-353 already uses.

## Changed

- `services/content_generation/itinerary_utils.py` — NEW. `ITINERARY_CLAMP_MIN/MAX`,
  `nudge_itinerary_day` (moved from `graph.py`, renamed from `_nudge_itinerary_day`),
  `parse_canonical_itinerary_days`, `serialize_itinerary_days`, `generated_day_word_counts`,
  `in_clamp`.
- `services/content_generation/graph.py` — `_process_itineraries` now calls
  `itinerary_utils.nudge_itinerary_day`; `_FAILURE_MAP` gains `ITINERARY_DAY_COUNT_MISMATCH` and
  `ITINERARY_STILL_COMPRESSED`; `_CODE_FIELD_MAP` gains both -> `"aa_itineraries"`; `validate_node`
  gains the two new checks (guarded: skipped entirely when the source itinerary has no reliable
  day markers, i.e. `parse_source_day_word_counts(...)["used_fallback"] is True`, to avoid firing
  on tours with no usable source to compare against).
- `services/content_generation/flag_fix_node.py` — `STAGE2_FIX_MAPPING` gains
  `"ITINERARY_STILL_COMPRESSED": "itineraries"`; `_DETERMINISTIC_SEO_CODES` gains
  `"ITINERARY_STILL_COMPRESSED"`; new `_repair_still_compressed_days` helper; `flag_fix_node` main
  body special-cases this code before the generic fix flow.
- `api/routers/admin_pipeline.py` — untouched (still imports `ITINERARY_CLAMP_MIN/MAX` from
  `graph.py`, still works via the re-export).

## Tradeoffs

- Re-parsing the itinerary string on every `validate_node` call (instead of trusting the cached
  `itinerary_day_ratios`) is a small amount of repeated CPU work (regex over a short string) in
  exchange for correctness across `revalidate_node`'s re-entry — judged clearly worth it.
- The day-count-mismatch check is SKIPPED (not "trust the model") whenever
  `parse_source_day_word_counts` falls back (fewer than 2 line-anchored day markers found in the
  source) — a tour with a genuinely unstructured source itinerary gets no day-count gate at all,
  rather than a guess. Consistent with the task's own emphasis on not firing on bad/no signal.
