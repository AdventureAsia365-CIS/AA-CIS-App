# AA-512 — [T8] Bỏ bước chọn Channel, angle ranking bằng số đo được

## Decisions

- **AA-511 (Slate) already shipped the "channel fixed from Subject, no choose-channel step"
  behaviour** via `services/acp_shared/slate.py::pick_subject()` — a separate, already-live entry
  point from the old `create_request()` atom-picker. Confirmed the atom-picker UI path
  (`SlotPickerPanel.tsx`) is already dead code (unused, per the epic's own documented "keep old
  code, stop using it, don't delete" convention). Decision: do NOT retire/delete
  `create_request()`/`set_channel()`/the Channel-picker UI — keep following that same convention.
  AA-512's real remaining scope is the one thing genuinely not built: **measurable angle
  ranking** (ADR 0004). See `docs/claude_audit/AA-512-step0-investigation.md` for the full
  evidence trail.
- **Segment/Route Score is NOT part of the 3-angle sort key.** It's constant across all 3 angles
  of the same Subject (already decided which Subject got proposed, AA-511's own job) — the
  reference implementation (`src/aa_social/angles.py::Angle.score`) doesn't include it either,
  despite ADR 0004's summary prose naming it as one of "3 measurable criteria". Shown once in the
  new fixed header instead of folded into a 3-way tie-break.
- **Scope narrowed to the channel's own avoid-list only**, not also brand-wide banned phrases
  (Ms. Thư's reference folds both in) — AA-512's own text says "avoid-list của Channel" and this
  ticket doesn't own brand-wide banned-phrase config.
- **Ranking only runs when `channel` is already known at generation time** (Subject-driven
  requests). The legacy atom-picker path (channel picked only at step 8, after angles exist)
  structurally cannot compute channel-scoped avoid-list violations before generation — kept on
  the old LLM-`recommended_index` behaviour, no regression.
- `walks` (the reference's 3rd ranking axis) is out of scope — AA-512's own text lists exactly 3
  axes (none is "walks"), and T8's prompt still only sees one representative atom (Route-aware
  context is AA-513's job).

## Changed

- Migration 135: `acp_shared.angle_gate_option` gains `answers`/`violations` (jsonb) — the
  server-verified ranking evidence, NULL when never ranked.
- `services/acp_angle_gate/ranking.py` (new) — `rank_angles()`, a disclosed port of
  `angles.py::rank()`'s real 2-axis sort (violations, then answers).
- `prompts.py`/`generate.py` — LLM now also claims `answers: list[str]` per angle (server
  re-verifies, never trusts); PAA pool shown to the LLM is now the FULL list, not capped at 5.
- `service.py::set_goal_and_generate()` — computes+persists measurable ranking when channel is
  known, overriding `recommended`; `fetch_request()` returns `answers`/`violations` per angle +
  a joined Subject header (`subject_score`/`subject_place`/`subject_action`/`subject_hub_name`).
- Frontend `AngleGateTab.tsx` — Subject-driven requests get a 3-step Stepper (Goal/Angle/Write,
  no Atom/Channel steps) + a fixed `SubjectHeader` (Channel + Score) + 2 measurable badges per
  angle card. Legacy atom-picker path renders exactly as before (5 steps), unchanged.

## Tradeoffs

- Did not refactor `pick_subject()` (slate.py) to call through `create_request()` — they still
  duplicate the INSERT shape. Consolidating was tempting but out of scope and riskier than
  leaving 2 working, independently-tested paths alone.
- `content_piece.channel`/`angle_gate_option_id` (migration 124) confirmed unaffected — already
  correctly wired by a prior session, no change needed.
