# AA-490 — dry_run preview: in-file dedup

## Decisions
- Mirrored the real Commit path's exact mechanism: `services/ingestion/handler.py`'s
  `normalize_group_key(src_name, provider)` + a `seen_keys` set, imported directly (not
  reimplemented) so preview and commit can never silently drift apart on what counts as a
  duplicate.
- Matched `process_file()`'s exact check ORDER too (in-file dedup checked BEFORE the DB-dup
  check), not just the mechanism — so preview and commit report the identical outcome for the
  identical file, not just "similar."
- New blocked-tour reason `duplicate_in_file`, distinct from the existing `duplicate_tour`
  (DB-dup) — the issue's own proposal asked for a visible distinction ("N tours ready, M sẽ bị
  bỏ do trùng trong file"), not a merged/ambiguous count.

## Changed
- `api/routers/admin_pipeline.py::ingest_s3()` (dry_run branch) — added `seen_keys` set +
  `normalize_group_key()` import, new `duplicate_in_file` blocked-tour reason ahead of the
  existing `duplicate_tour`/`missing_fields` checks.
- `frontend/app/admin/upload/page.tsx` — `BlockedTour.reason` type gains `duplicate_in_file`;
  Blocked Tours table shows a distinct "Duplicate in File" badge + the real backend `message`
  text (previously hardcoded "Already in catalog" for every non-missing-fields reason).
- `tests/unit/test_aa490_dry_run_infile_dedup.py` — 4 new tests (in-file dup flagged, case/
  whitespace-insensitive match, different provider not flagged, DB-dup still takes the correct
  branch even with the new check ahead of it).

## Tradeoffs
- Did not add a distinct `duplicate_in_file_count` field — `blocked_count` (already in the
  response) plus each row's own `reason` in `blocked_tours` gives the same information the
  issue asked for ("M sẽ bị bỏ do trùng trong file") without adding a parallel count that could
  drift from the per-row reasons.
- Preview's in-file dedup only sees `records[:req.max_tours]` (existing pre-existing limitation
  of the preview slice, applies equally to the DB-dup check already there) — not something this
  fix introduces or was asked to change.
