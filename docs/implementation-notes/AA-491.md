# AA-491 — Gỡ --ignore cho test_h3_rule_extractor.py + test_run_health.py

## Decisions
STEP0 (mandatory per issue) ran both files with the CI's exact env vars first — real cause
confirmed for both files, NEITHER of the issue's own 2 unconfirmed hypotheses
(`LANGFUSE_PUBLIC_KEY` missing, DB fixture missing) turned out to be the cause:

- **`test_h3_rule_extractor.py` (3 fails)** — a real, pre-existing MOCK/SIGNATURE MISMATCH.
  `_call_haiku()`'s real return type is `tuple[dict, int, int]`
  (`extracted, in_tok, out_tok = _call_haiku(...)`). The test's `_haiku_response()` helper
  returned a bare 6-key dict. Unpacking a 6-key dict into 3 names raises exactly
  `"too many values to unpack (expected 3)"` — silently caught by
  `extract_and_save_rule()`'s own `except Exception` (logged as `h3_haiku_failed`, returns
  `None`) — every assertion expecting a real rule_id failed. Real fix: `_haiku_response()` now
  returns the same `(dict, int, int)` shape `_call_haiku()` really returns.
- **`test_run_health.py` (4 fails)** — a much bigger, real finding: AA-441 (already shipped,
  Done) rewrote `GET /admin/acp/run-health` from the legacy v1 tables
  (`acp_shared.acp_runs`/`acp_stage_runs`/`acp_hitl_requests`/`acp_silver_s4.blog_drafts`) to
  the real, live v2 tables (`acp_shared.acp_v2_runs`/`acp_v2_slots`) — see
  `api/routers/acp_health.py`'s own docstring on `get_run_health()`. This test file's mock
  (`_build_app_with_mock_pool`) still matched SQL text against the OLD v1 table names, which no
  longer appear anywhere in the real query — every mocked `conn.fetch()` call fell through to
  `return []`, so **every** endpoint test got 0 rows back regardless of what fixture data was
  passed in. `test_run_health_filters_by_tenant` happened to still "pass" only because its
  assertion (`all(r["tenant_id"] == X for r in data)`) is vacuously true on an empty list —
  it was never actually testing anything real either; strengthened while fixing.
  - AA-441's docstring also documents 3 real, DELIBERATE, permanent-for-now gaps in the v2
    path (not bugs): `check_stage_slo()` doesn't recognize v2 `channel:kind` stage names (so
    `stuck` can never be True), `acp_v2_runs` has no cost column (`cost_cap_breached` can never
    be True, cost is hardcoded 0.0 = "not tracked"), and there's no v2 equivalent to
    `acp_hitl_requests` yet (`gate_statuses` is always all-`None`). The 3 corresponding tests
    were written against the OLD v1 shape, asserting these COULD be True — a scenario the
    current code structurally cannot produce. Rewrote them to assert the real, current,
    documented v2 behavior instead (still real regression coverage — they'd fail the moment
    someone wires v2 tracking back in without updating these) rather than deleting them or
    forcing a fake pass.

## Changed
- `tests/acp/test_h3_rule_extractor.py` — `_haiku_response()` now returns `(dict, in_tok,
  out_tok)`, matching `_call_haiku()`'s real signature. No other line changed.
- `tests/acp/test_run_health.py` — full fixture rewrite: `_make_run()` matches
  `acp_v2_runs`'s real SELECTed columns (no `country`/cost/`error_message`, which don't exist
  on that table); `_make_stage()` replaced by `_make_slot()` matching `acp_v2_slots`'s real
  columns; `_make_hitl()` removed (endpoint no longer queries any hitl table);
  `_build_app_with_mock_pool()` mocks `acp_v2_runs`/`acp_v2_slots`, not the v1 tables. 3 of the
  6 endpoint tests renamed + rewritten to assert the real current v2 behavior (see Decisions).
- `.github/workflows/ci.yml` — removed
  `--ignore=tests/acp/test_h3_rule_extractor.py --ignore=tests/acp/test_run_health.py`;
  `pytest tests/acp/` now runs the full 6-file, 75-test suite, blocking, no exclusions.

## Tradeoffs
- Did not build real v2 SLO/cost/gate tracking (that's a substantial separate feature, well
  outside this issue's "gỡ --ignore" cleanup scope) — the 3 rewritten tests document the gap
  and will need a follow-up rewrite themselves once that tracking is built, at which point
  their current "always False/None" assertions are the FIRST thing that should break.
- Renamed 3 test methods (`test_stuck_run_detection` →
  `test_stuck_detection_never_fires_for_v2_slots_yet`, etc.) rather than keeping the old names
  with inverted assertions — the old names actively misdescribed what the test now proves
  (asserting the OPPOSITE of what the name implies would be worse than a clear rename).
