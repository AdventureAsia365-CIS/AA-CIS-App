## 1. Channel routing for gate_fns — recommend: each gate self-checks, orchestrator untouched

`aamc/gates.py`'s own F4/F5 already establish the pattern:
```python
def gate_structural_variance(piece: Piece) -> GateResult:
    if piece.channel != "blog":
        return GateResult(gate="F4_structural_variance", passed=True)
    ...
```
Recommend the same shape for every new DET gate here: **the gate function takes `channel` (or
enough context to know it) and no-ops/branches internally.** `run_gates()`'s
`Callable[[str], GateResult]` signature and `pipeline.py`'s closure-binding convention (D5,
AA-364.md — every gate already gets its extra context bound via a closure, e.g. `lambda: gate_framework(piece_body, framework)`) already supports this with zero orchestrator change:
```python
def _f4(body: str) -> GateResult:
    return gate_structural_variance(body, piece.channel)
```
No `run_gates()` signature change, no new orchestrator parameter. This is the "less invasive"
option the task asked me to prefer, and it's not a new pattern — it's the one the ported
reference code already uses.

## 3. F9 social rubric (NEW) — minimal, separate failure-code vocabulary

Proposal: a second function, `gate_brand_seo_audit_social()`, own fixed vocabulary
`SOCIAL_SEO_FAILURE_CODES` (NOT merged into `BRAND_SEO_FAILURE_CODES` — keeps the blog
vocabulary's meaning stable for any future N8 flywheel dashboard querying it, per that codebase
already treating fixed vocabularies as append-only-per-domain, not a shared free-for-all).

**Facebook (3 fields)**: `brand_fit` (1/0), `cta_clear` (1/0 — caption has an unambiguous single
action, not a vague sign-off), `human_read` (1/0 — reads like a person, not templated AI copy).
Failure codes: `SUMMARY_OFF_BRAND`, `CTA_MISSING_OR_WEAK` (new), `GENERIC_AI_WORDING`,
`FACT_CHECK_MANUAL_CHECK`. Caption length (50-120 per `adapt.py`'s own instruction) and hashtag
count (≤5) are DET-checkable from the text and should NOT be LLM-judged — recommend adding them
as cheap assertions inside the DET gate stack (a tiny channel-specific check, could piggyback on
F4/structural-variance's per-channel branch, see §5) rather than spending an LLM field on them.

**TikTok (2 fields)**: `hook_strength` (1/0 — the HOOK line would stop a scroll in the first
second, evidence = the quoted hook), `cta_clear` (1/0 — SCRIPT ends with an actual call to
action, not just a fact). Failure codes: `CTA_MISSING_OR_WEAK`, `GENERIC_AI_WORDING`,
`FACT_CHECK_MANUAL_CHECK`. **Banned-pattern check deliberately excluded from this rubric** — per
the task's own steer, reuse whatever the F2 DET banned-pattern gate (§4) already produces
rather than re-asking the LLM to also police brand-voice red lines it's unreliable at enforcing
consistently (`CONTEXT.md` §1.6 itself ranks the deterministic lexicon scan ABOVE the LLM rubric
in the anti-AI-voice stack for exactly this reason — leverage/cost).

`status` field (`pass|flagged|manual_check`) and the review-order/uncertain→manual_check
convention carry over unchanged from F9-blog — no reason to diverge there.

## 7. F6 route-to-sellable — concrete definition proposed, needs Nghiep confirmation

**Proposed definition** (already load-bearing precedent, not invented here): AA-364.md's own
"should know" section already named this the ONE gap with zero coverage and already pointed at
the concrete field — `acp_deliver.tenant_tour_pages` (migration 078): `PRIMARY KEY (tenant_id,
tour_id)`, columns `url`, `url_alive BOOLEAN DEFAULT true`, `last_checked_at`. Proposed gate:

1. `cta_target` (from `Brief.cta_target`/`slot.cta_target`) must be non-empty — no CTA = dead
   end, same as `aamc/gates.py`'s original F6.
2. Resolve `slot.trip_id` (UUID, already on `Slot` — `services/acp_planning/models.py:110`) →
   `SELECT url_alive FROM acp_deliver.tenant_tour_pages WHERE tenant_id=$1 AND tour_id=$2`.
   `url_alive IS NOT TRUE` (false OR no row at all) → FAIL. **No-row = fail-closed, not
   fail-open** — matches L6 ("never fail silently"; an untracked page is an unknown, and unknowns
   route to a stated fail, not a silent pass, per `CONTEXT.md` §1.2's calibration boundary law).
3. For `channel=="blog"` only: `cta_target` (or its URL) must literally appear in
   `body_tagged` — ported unchanged from `aamc/gates.py`'s own channel branch
   (`if piece.channel == "blog" and cta not in body`). FB/TikTok captions reference the trip
   conversationally (no literal URL in a caption — see `adapt.py`'s actual output shape), so this
   sub-check is skipped for those channels, same as the original prototype already decided.

**What needs Nghiep's confirmation, not assumed**: (a) is `tenant_tour_pages.url_alive` actually
kept fresh for this tenant today, or would this gate hold almost everything on stale/unpopulated
rows right now (worth a quick DB check before wiring this live, separate from this design step);
(b) fail-closed-on-no-row (proposed above) vs. some softer "manual_check" status for untracked
pages — I lean fail-closed per L6, but this changes how often pieces hold, so it's a real product
choice, not just a technical one.
