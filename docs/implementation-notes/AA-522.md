# AA-522 — Write flow doesn't save on reload + Luồng B (legacy 5-step atom-picker) removed

## Decisions

- **No new `awaiting_cta` boolean column.** The Linear comment's diagnosis suggested one as an
  example fix. Instead: added `GET /v1/content-writing/requests/{id}/latest-piece`
  (`fetch_latest_piece_for_request()`), and the FE's write-step now asks this on every load
  instead of trusting local React state. Whether a CTA is still needed is fully derivable from
  existing fields (`angle_gate_request.cta` + "does a `content_piece` already exist for the
  currently-chosen angle option") — a new flag would just be a second source of truth for
  something already knowable, with a real risk of drifting out of sync with it.
- **The "latest piece" lookup is scoped to the CURRENTLY CHOSEN angle option**, not just "latest
  by created_at for this request_id" — same option-id-first / chosen=true-fallback convention
  `fetch_review()` already uses. Without this, a "Change angle" (reopen + re-choose a different
  angle) would show the PREVIOUS angle's stale piece instead of correctly treating the new angle
  as needing a fresh write.
- **Consolidated write-triggering into ONE `useEffect`** (keyed on `req.status === 'approved'`,
  guarded by a ref so it fires once per request_id) instead of the old pattern of inline
  `writeContent()` calls scattered across `choose()`/`submitChannel()`'s success handlers. This
  is what actually fixes the bug for every path that can land on the write step — a fresh choose,
  a resumed reload, and a reopen+re-choose cycle all go through the exact same "ask the server
  what's really going on" logic, not three separately-written triggers that a reload could bypass.
- **Removed Luồng B (`create_request()`/`set_channel()`, atom-only creation + the post-choice
  Channel step) entirely, backend included, not just the FE dropdown.** Verified live (real
  DB query via S3-mediated ECS exec, 21 real rows in `acp_shared.angle_gate_request`) that
  **zero** rows are mid-flight in a state this would orphan (`status='approved' AND channel IS
  NULL AND subject_id IS NULL` — the only state a in-progress Luồng B session could be caught in
  by this deploy) before removing it. `set_channel()`'s own AA-451 slot-CTA prefill
  (`_fetch_slot_cta()`/`_compute_and_persist_slot_cta()`) was already 100% unreachable for the
  current Subject-driven flow (channel is fixed at creation, so the FE Channel-step card — its
  only caller — never rendered for a Subject-driven request) — removing it is not a regression,
  it's deleting code that could never fire.
- Removed the now-fully-dead `SlotPickerPanel.tsx` (the pre-AA-511 Weekly Slots panel,
  unreferenced by any rendered page since `PlanningTab.tsx` switched to `SlateTab.tsx`) in the
  same PR — it was the FE source of the `?atom_id=` handoff Luồng B's atom-picker still accepted.

## Changed

- `services/acp_angle_gate/service.py` — deleted `create_request()`, `set_channel()`,
  `InvalidChannelError`, `_fetch_slot_cta()`, `_compute_and_persist_slot_cta()`, `_SLOT_CTA_QUERY`.
  Added nothing new here (the new endpoint's logic lives in `acp_content_writing`).
- `services/acp_content_writing/service.py` — added `fetch_latest_piece_for_request()` +
  its 2 queries (`_CHOSEN_OPTION_QUERY`, `_LATEST_PIECE_FOR_OPTION_QUERY`).
- `api/routers/v1_angle_gate.py` — deleted `POST /requests` (atom-only create) and
  `POST /requests/{id}/channel`, their pydantic bodies, and the now-unused `Optional` import.
- `api/routers/v1_content_writing.py` — added `GET /requests/{id}/latest-piece`.
- `frontend/.../AngleGateTab.tsx` — rewritten: no more raw atom dropdown, no Channel-step card,
  no `?atom_id=` handling; a `!req` state now shows an empty state pointing at the Slate. Write
  step's auto-fire logic consolidated into one `useEffect` (see Decisions). 3-step Stepper
  (Goal/Angle/Write) always, `SUBJECT_STEP_LABELS`/`STEP_LABELS` duality removed.
- `frontend/.../SlotPickerPanel.tsx` — deleted (dead code, see Decisions).
- `frontend/.../t8-angle-gate/page.tsx` — comment updated (behavior unchanged, still wraps
  `AngleGateTab` in `<Suspense>` for `useSearchParams()`).
- Tests: `test_aa449_angle_gate_service.py` (removed `TestCreateRequest`/`TestSetChannel` +
  their fixtures), `test_aa449_v1_angle_gate.py` (removed the matching router-level classes),
  `test_aa450_cta_slot_lookup.py` (removed `TestFetchSlotCta`, kept `TestFetchRequestIncludesCta`),
  `test_aa450_content_writing_service.py` (added `TestFetchLatestPieceForRequest`, 4 cases),
  `test_aa450_v1_content_writing.py` (added `TestGetLatestPiece`, 2 cases).

## Tradeoffs

- Deleting the backend Luồng B code (not just the FE) is a bigger diff than the issue's literal
  wording ("gỡ dropdown atom thô") strictly required, but leaving `create_request()`/
  `set_channel()` alive with zero real callers is exactly the kind of orphaned path this issue
  is about in the first place — and AA-526 (next in this chain) is about to change how/where
  atoms are even sourced from, so touching this surface once now is cheaper than twice.
- Did not add a `/change channel` FE action some old comments in the deleted code speculated
  about — channel is fixed at Subject-pick time now, no product ask for changing it exists.
