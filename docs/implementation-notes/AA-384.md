# AA-384 — Đổi hướng Mirror/posts_per_week + UI Marketplace đúng repo + đồng bộ CLAUDE.md

Bundled task, 3 parts. Linear: https://linear.app/aa-ecosys/issue/AA-384

## Decisions

- **posts_per_week storage**: new `shared.tenants.posts_per_week` column (migration 099), not a
  new table. Parallels `plan_tier` — both are per-tenant attributes set at creation.
  `plan_tier` is kept as-is (still drives `PLAN_LIMITS` rpm/quota — a billing concern, unrelated
  to posts_per_week now).
- **Backfill**: existing tenant rows get their posts_per_week backfilled from the OLD
  `POSTS_PER_WEEK_BY_PLAN_TIER` map values (same numbers they were implicitly using via Mirror
  before this change), then the column goes NOT NULL + CHECK 1-14. New tenants must supply a
  value explicitly — no default.
- **Mirror wording**: kept `runway_months()` call byte-for-byte (per explicit instruction —
  formula does not change), only replaced the `upsell_suggestion` block + `_PLAN_TIER_UPGRADE_ORDER`
  constant with a plain informational message. No plan-tier upgrade path is computed anymore.
- **assigned_angle**: untouched, per instruction — quality mechanism, not commercial.
- **Marketplace UI location**: `frontend/app/admin/marketplace/page.tsx` in AA-CIS-App, following
  the exact pattern of `frontend/app/admin/tenants/page.tsx` (AdminSidebar + adminUi helpers +
  `/api/admin/[...path]` proxy, inline-style React, no new UI library). AA-ACP-App is not touched —
  abandoned repo, 0 traffic since 09/07/2026.

## Tradeoffs

- **posts_per_week surfaced in `list_tenants()`**: not explicitly requested by the issue, but the
  issue's own point 1 has no other UI-visible place to see what cadence an existing tenant chose
  once Mirror's tier-derived value goes away — added it to the existing list query rather than
  leave it invisible outside of Mirror.
- **Mirror UI location**: the issue says "Mirror UI thi ap dung wording moi" but no Mirror UI
  existed anywhere yet (confirmed: the abandoned AA-ACP-App Marketplace page never had one either
  — grep-confirmed before building). Put it as a tab on the existing Tenants detail panel (natural
  home, reuses the existing tab pattern) rather than inventing a new standalone page or bolting it
  onto the Marketplace catalog/portfolio flow, which is a different step of onboarding.
- **CLAUDE.md ECS/deploy numbers**: left explicitly marked "unverified" rather than guessed —
  AWS was stopped this session, no live check was possible, and the instruction is to record real
  state, not invent a plausible one.
